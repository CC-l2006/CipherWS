# CipherWS 后端微服务架构

> 版本：v1 ｜ 状态：已落地并本地联调通过 ｜ 落地时间：2026-10-05
>
> 本文描述 `server/` 后端由**单体**改造为 **Spring Cloud Alibaba 微服务**后的结构、依赖、配置与运行方式。
> 注册中心 / 配置中心的容器部署见 [Nacos容器部署.md](./Nacos容器部署.md)，整体分层视图见 [分层架构.md](./分层架构.md)。

## 一、改造前后对比

| 维度 | 改造前（单体） | 改造后（微服务） |
| --- | --- | --- |
| 工程结构 | `server/` 单 Maven 工程 | `server/` 聚合父工程 + 4 个子模块 |
| 部署形态 | 1 个 jar / 1 进程 / 1 端口(8080) | 3 个可执行服务 + 1 个公共 jar |
| 服务注册 | 无 | 全部注册到 Nacos |
| 服务发现 / 负载均衡 | 无 | Nacos Discovery + Spring Cloud LoadBalancer |
| 服务间调用 | 同进程方法调用 | OpenFeign 声明式调用 |
| 统一入口 | 无（前端直连后端） | Spring Cloud Gateway |
| 配置管理 | 本地 `application.properties` | Nacos 配置中心 + 本地兜底 |

改造未改变任何业务接口语义：`/say/saying`、`/audio/stream` 的入参、返回结构、状态码与原来完全一致，仅把**访问入口**从后端端口换成了网关端口。

## 三、模块结构

```
server/
├── pom.xml                      # 父工程（packaging=pom）：版本管理 + 模块聚合
├── cipherws-common/             # 公共模块（jar）
│   └── org.example.cipherws.common
│       ├── result/Result.java       # 统一响应结构
│       ├── entity/Say.java          # 领域实体
│       └── api/SayClient.java       # OpenFeign 服务契约（@FeignClient）
├── cipherws-say-service/        # 业务服务（可执行 jar）→ 注册 Nacos
│   └── org.example.cipherws.say
│       ├── SayServiceApplication.java
│       ├── config/{WebConfig,SayingConfig}.java
│       ├── controller/{SayController,AudioController}.java
│       ├── service/**                # SayService / AudioService 及其实现
│       └── resources/{application.yml, saying.json, music/**}
├── cipherws-portal-service/     # 门户聚合服务 BFF（可执行 jar）→ 注册 Nacos
│   └── org.example.cipherws.portal
│       ├── PortalServiceApplication.java   # @EnableFeignClients
│       └── controller/PortalController.java
└── cipherws-gateway/            # API 网关（可执行 jar，WebFlux）→ 注册 Nacos
    └── org.example.cipherws.gateway
        ├── GatewayApplication.java
        └── resources/application.yml       # Nacos 发现 + 路由规则
```

### 各模块职责

| 模块 | 打包 | 职责 | 是否注册 Nacos |
| --- | --- | --- | --- |
| `cipherws-common` | jar（库） | 统一响应 `Result`、实体 `Say`、**OpenFeign 契约** `SayClient`；被各服务依赖 | 否（纯依赖库） |
| `cipherws-say-service` | 可执行 jar | 原单体业务：名言查询 + 音频流；实现 Feign 契约 | 是，服务名 `cipherws-say-service` |
| `cipherws-portal-service` | 可执行 jar | 门户聚合（BFF）：用 **OpenFeign** 调 say 服务；后续聚合点 | 是，服务名 `cipherws-portal-service` |
| `cipherws-gateway` | 可执行 jar | 统一入口，按路径把请求经 Nacos 路由到后端服务 | 是，服务名 `cipherws-gateway` |

## 四、依赖关系与调用链

```
                    ┌────────────────────────────┐
  前端 / 浏览器 ───▶│  cipherws-gateway  :8080    │  （Spring Cloud Gateway，WebFlux）
                    │  仅做路由转发，不含业务逻辑  │
                    └───────┬────────────┬───────┘
                            │ lb://      │ lb://
              /say/** /audio/**          /portal/**
                            ▼            ▼
                ┌───────────────────┐  ┌────────────────────────┐
                │ cipherws-say-     │  │ cipherws-portal-service │
                │ service  :8081    │◀─┤  :8082  (BFF)           │
                │ 名言 + 音频        │  │  OpenFeign → SayClient  │
                └─────────┬─────────┘  └───────────┬────────────┘
                          │                        │
                          └──────────┬─────────────┘
                                     ▼
                         ┌───────────────────────┐
                         │  Nacos  :8848         │
                         │  注册中心 + 配置中心   │
                         └───────────────────────┘
```

- 网关与服务、服务与服务之间**不写死 IP**，统一经 **Nacos 服务发现**解析实例，再由 **Spring Cloud LoadBalancer** 选择实例。
- 网关用 `lb://<service-name>` 声明式路由；`cipherws-portal-service` 用 **OpenFeign** 做声明式调用。

## 五、端口规划

| 服务 | 端口 | 说明 |
| --- | --- | --- |
| `cipherws-gateway` | `8080` | **对外唯一入口**（前端 `VITE_API_BASE_URL` 指向这里，沿用原后端端口） |
| `cipherws-say-service` | `8081` | 业务服务，仅内网可达 |
| `cipherws-portal-service` | `8082` | 聚合服务，仅内网可达 |
| Nacos 控制台 | `8849` | 容器内仍是 8080，宿主映射到 8849（避开网关占用的 8080），见 docker 文档 |
| Nacos 主端口 | `8848` / `9848` | 客户端注册与 gRPC |

> 端口均可用环境变量覆盖：`SERVER_PORT`、`NACOS_SERVER_ADDR`、`NACOS_USERNAME`、`NACOS_PASSWORD`、`NACOS_NAMESPACE`、`NACOS_GROUP`。

## 六、Nacos 集成

### 6.1 依赖

每个可执行服务都引入（`cipherws-common` 只提供契约，不引入注册）：

```xml
<dependency>
  <groupId>com.alibaba.cloud</groupId>
  <artifactId>spring-cloud-starter-alibaba-nacos-discovery</artifactId>
</dependency>
<dependency>
  <groupId>com.alibaba.cloud</groupId>
  <artifactId>spring-cloud-starter-alibaba-nacos-config</artifactId>
</dependency>
```

### 6.2 注册发现配置（以 say 服务为例）

```yaml
spring:
  application:
    name: cipherws-say-service          # 注册到 Nacos 的服务名
  cloud:
    nacos:
      server-addr: ${NACOS_SERVER_ADDR:127.0.0.1:8848}
      username: ${NACOS_USERNAME:nacos}
      password: ${NACOS_PASSWORD:nacos}
      discovery:
        namespace: ${NACOS_NAMESPACE:}
        group: ${NACOS_GROUP:DEFAULT_GROUP}
      config:
        namespace: ${NACOS_NAMESPACE:}
        group: ${NACOS_GROUP:DEFAULT_GROUP}
        file-extension: yaml
  config:
    import:
      - optional:nacos:cipherws-say-service.yaml   # 配置中心（可选，缺失也能启动）
```

要点：

- `spring.application.name` 就是服务名，网关路由与 Feign 都以它为准；
- `spring.config.import` 用 **`optional:`** 前缀，Nacos 中即使没有对应 dataId 也不影响启动；
- 生产环境把 `NACOS_USERNAME/PASSWORD/NAMESPACE` 用环境变量注入，不要硬编码。

## 七、OpenFeign

### 7.1 契约定义在公共模块

`cipherws-common`：

```java
@FeignClient(name = "cipherws-say-service", path = "/say", contextId = "sayClient")
public interface SayClient {
    @GetMapping("/saying")
    Result saying(@RequestParam("id") int sayId);
}
```

### 7.2 提供方实现契约

`cipherws-say-service` 的 `SayController` 直接 `implements SayClient`，
这样**服务端实现与调用方契约天然一致**，改接口时编译期即可发现不一致。

### 7.3 调用方启用 Feign

`cipherws-portal-service`：

```java
@SpringBootApplication
@EnableFeignClients(basePackages = "org.example.cipherws.common.api")
public class PortalServiceApplication { /* ... */ }

@RestController
@RequestMapping("/portal")
public class PortalController {
    private final SayClient sayClient;         // 直接注入契约
    public PortalController(SayClient sayClient) { this.sayClient = sayClient; }

    @GetMapping("/say/{id}")
    public Result say(@PathVariable int id) {
        return sayClient.saying(id);           // 经 Nacos 发现 → 负载均衡 → say 服务
    }
}
```

### 7.4 两个必须注意的坑（本项目已处理）

1. **Feign 必须显式引入 LoadBalancer**：Spring Cloud 2025 的 `spring-cloud-starter-openfeign`
   不再默认带负载均衡，须额外加 `spring-cloud-starter-loadbalancer`，
   否则启动报 `No Feign Client for loadBalancing defined.`。
2. **不要在响应式（WebFlux）线程里直接调用 Feign**：Spring Cloud Gateway 是 WebFlux，
   事件循环线程禁止阻塞；而 Feign 是阻塞客户端（内部会 `block()`）。
   因此 **Feign 调用放在 servlet 栈的 `cipherws-portal-service`**，
   网关保持轻量只做转发——这也是本项目把「网关」与「聚合服务」拆成两个模块的原因。

## 八、网关路由

`cipherws-gateway/src/main/resources/application.yml`：

```yaml
spring:
  cloud:
    gateway:
      server:
        webflux:                 # Gateway 4.3 起使用 server.webflux.* 命名空间
          discovery:
            locator:
              enabled: false     # 用显式路由，不自动暴露所有服务
          routes:
            - id: cipherws-say-service
              uri: lb://cipherws-say-service
              predicates:
                - Path=/say/**
            - id: cipherws-audio-service
              uri: lb://cipherws-say-service
              predicates:
                - Path=/audio/**
            - id: cipherws-portal-service
              uri: lb://cipherws-portal-service
              predicates:
                - Path=/portal/**
```

> 演示阶段关闭了 `discovery.locator`（自动为每个服务生成 `/<service-id>/**` 路由），
> 以便精确控制对外路径；如需要自动路由可将其置为 `true`。

## 九、构建与运行

### 9.1 构建

```bash
cd server
./mvnw clean package            # 编译 + 测试 + 打包（Windows 用 mvnw.cmd）
./mvnw -DskipTests package      # 跳过测试打包
```

产物：

```
cipherws-say-service/target/cipherws-say-service-0.0.1-SNAPSHOT.jar
cipherws-portal-service/target/cipherws-portal-service-0.0.1-SNAPSHOT.jar
cipherws-gateway/target/cipherws-gateway-0.0.1-SNAPSHOT.jar
```

### 9.2 启动顺序

1. 先启动 Nacos（见 [Nacos容器部署.md](./Nacos容器部署.md)）；
2. 依次启动业务 / 聚合 / 网关服务（顺序不强制，注册有重试）。

```bash
# 在 server/ 目录下
java -jar cipherws-say-service/target/cipherws-say-service-0.0.1-SNAPSHOT.jar
java -jar cipherws-portal-service/target/cipherws-portal-service-0.0.1-SNAPSHOT.jar
java -jar cipherws-gateway/target/cipherws-gateway-0.0.1-SNAPSHOT.jar
```

（也可用 `./mvnw -pl cipherws-say-service spring-boot:run` 等命令逐个启动。）

### 9.3 本地联调用例（已实测）

```bash
# 1) 网关 → say 服务（静态路由）
curl "http://127.0.0.1:8080/say/saying?id=1"
# {"success":true,"errorMsg":null,"data":{"id":1,"saying":"青年时种下什么，老年时就收获什么。","person":"易卜生"},"total":null}

# 2) 网关 → portal 服务 → OpenFeign → Nacos → say 服务
curl "http://127.0.0.1:8080/portal/say/2"
# {"success":true,"errorMsg":null,"data":{"id":2,"saying":"路漫漫其修远兮，吾将上下而求索。","person":"屈原"},"total":null}

# 3) 网关 → say 服务（音频 Range 分段）
curl -r 0-9 -o /dev/null -w "%{http_code}\n" \
  "http://127.0.0.1:8080/audio/stream?audio=HOYO-MiX%20-%20Da%20Capo.mp3"
# 206
```

## 十、与前端 / 部署的衔接

- 前端基础地址保持 **8080** 不变（`.env.development` → `http://127.0.0.1:8080`），
  由网关监听 8080 来适配前端；这样前端无需改动。
- 云服务器上，网关 `8080` 对外，`8081/8082/8848/9848` 仅本机/内网；
  接入 nginx 后可由 nginx 反代 `8080`，进一步收敛暴露面。

## 十一、改造时顺带修正的问题

| 问题 | 原实现 | 现实现 |
| --- | --- | --- |
| `saying.json` 读取路径 | `new File("src/main/resources/saying.json")`，依赖运行目录，打包后失效 | `SayingConfig` 用 `ClassPathResource` 从 classpath 读取 |
| 音频路径 | `application.properties` 里写死 Windows 绝对路径 `F:/Java/.../music` | `resource.path.audio.music` 默认 `classpath:music/`，可用环境变量覆盖 |
| 音频路径穿越 | 未校验 | 拦截 `..`、`/`、`\`，非法名称返回 400 |
| 名言越界 | 非法 id 抛 `IndexOutOfBoundsException` | 先做边界判断，返回 `Result.fail("id错误")` |
| 端口冲突 | 后端占用 `8080` | 网关沿用 `8080`（适配前端），say/portal 内部服务用 `8081/8082`，Nacos 控制台宿主端口移到 `8849` |

## 十二、后续演进方向

- **配置中心**：把 `cipherws-*.yaml` 真正推入 Nacos，实现配置热更新（当前 `import` 已就绪，仅需补充 dataId 内容）；
- **限流熔断**：接入 `spring-cloud-starter-alibaba-sentinel` 做网关与服务的限流、熔断、降级；
- **分布式事务**：数据落库后如有跨服务写需求，引入 `seata`；
- **可观测性**：接入 Micrometer + Prometheus/Grafana、链路追踪（Micrometer Tracing）；
- **服务扩容**：say 服务无状态，可直接多实例部署，由网关与 Feign 自动负载均衡。
