# 项目本地工具链（`deploy/.tools/`）

> 记录时间：2026-10-05

`deploy/.tools/` 存放**只服务于本项目**的工具，避免污染系统全局环境。整个目录已被
`.gitignore` 排除（体积大，且可由目录内的脚本随时重建）。

## 目录结构

```
deploy/.tools/
├── jdk-17/              # Temurin JDK 17.0.20.1（完整 JDK，约 303 MB，含 jmods/javac）
├── fetch-jdk17.ps1      # 重新安装 JDK 17 的脚本（下载 + SHA256 校验 + 解压）
└── dev-env.ps1          # 仅对当前终端注入 JAVA_HOME / PATH
```

## 为什么不用全局环境

本机系统 `JAVA_HOME` 为空、系统 `PATH` 中也没有 `java`。项目通过
`deploy/.tools/jdk-17` + `dev-env.ps1` 提供 JDK，**不改注册表、不改系统环境变量**，
换机器只需重跑一次安装脚本。

> 启动脚本时若报「禁止运行脚本」，是 PowerShell 执行策略（本机为 Restricted）所致，
> 用下面的 `-ExecutionPolicy Bypass` 形式，或先执行
> `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`。

## 一、安装 / 重装 JDK 17

```powershell
# 在项目根目录执行
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\.tools\fetch-jdk17.ps1
```

脚本特性：

| 特性 | 说明 |
| --- | --- |
| 下载源 | 清华 TUNA 镜像的 Adoptium 17（`OpenJDK17U-jdk_x64_windows_hotspot_17.0.20.1_1.zip`） |
| 完整性 | 下载后校验 SHA256，与 Adoptium 官方 API 给出的值比对，不匹配直接报错 |
| 下载器 | 优先 `Start-BitsTransfer`，失败回退 `curl`（镜像会拒绝无 User-Agent 的请求） |
| 幂等 | 已安装则跳过；安装包大小正确则跳过下载 |
| 编码 | 脚本为纯 ASCII，兼容 Windows PowerShell 5.1 的 ANSI 读取方式 |

## 二、启用 JDK（仅当前终端）

```powershell
# 在项目根目录执行（注意开头的点，表示点源）
. .\deploy\.tools\dev-env.ps1

# 之后即可正常构建
cd server
.\mvnw.cmd clean package
```

关闭该终端后 `JAVA_HOME` / `PATH` 自动失效，不影响其他终端。

## 三、验证

```powershell
java -version          # 期望 openjdk version "17.0.20.1" (Temurin)
cd server
.\mvnw.cmd -v          # 期望 Java version: 17.0.20.1, runtime: ...\deploy\.tools\jdk-17
```

## 四、注意事项

- **必须是 JDK 17**：父 POM 中 `maven.compiler.release=17`，用更高版本编译会报错。
- IDEA 的 Project SDK 指到 `deploy/.tools/jdk-17`，语言级别保持 **17**（不要设成更高的 JDK 级别）。
- 想换安装位置或版本，只需改 `fetch-jdk17.ps1` 顶部的 4 个变量（文件名、源地址、SHA256、字节数）。
- 本目录**不放文档**：项目约定所有说明统一放在 `docs/<日期>/` 下（即本文件）。
