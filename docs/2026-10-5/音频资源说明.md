# 音频资源说明（`music/` 与 `deploy/music/`）

> 记录时间：2026-10-05
>
> 结论先行：**音频文件不入库**。代码区的
> `server/cipherws-say-service/src/main/resources/music/` 已被 `.gitignore`
> 整个目录排除，里面不再放任何文件；音频统一放在仓库外的 `deploy/music/`。

## 一、为什么要移出版本库

`src/main/resources/music/` 原有 14 个音频文件，合计 **约 131 MB**（最大单个 13.8 MB）。

| 问题 | 说明 |
| --- | --- |
| 仓库永久变重 | 文件进了 Git 历史就永远在里面，之后再删也不会让仓库变小，`git clone` 一直慢 |
| 触碰 GitHub 硬限制 | 单文件上限 100 MB，一旦有文件超标 push 会被直接拒绝，且很难收拾 |
| 属于可外部分发的资源 | 和 `docker/*.tar` 镜像同一性质，仓库自己的 `.gitignore` 已有同类约定 |

移除后 `cipherws-say-service` 的 jar 从 **186 MB 降到 56 MB**（音频不再进 classpath）。

## 二、音频现在放哪

放在**仓库外**的 `deploy/music/`（该目录同样被 `.gitignore` 排除），
或用移动硬盘 / 网盘 / 对象存储另行分发后落到任意磁盘目录。

```
deploy/
├── music/                          # 放音频，不入库（约 131 MB）
│   ├── HOYO-MiX - Da Capo.mp3
│   └── ...
└── run-services.ps1                # 启动时自动注入 AUDIO_MUSIC_PATH
```

## 三、怎么让它生效

后端配置项是 `resource.path.audio.music`：

```yaml
# server/cipherws-say-service/src/main/resources/application.yml
resource:
  path:
    audio:
      music: ${AUDIO_MUSIC_PATH:classpath:music/}
```

### 方式一：用 `deploy\run-services.ps1`（推荐）

脚本启动服务时会**自动**把 `AUDIO_MUSIC_PATH` 指向 `<项目根>/deploy/music/`
（目录存在时），启动日志会打印一行：

```
Audio dir  : file:D:/GraduationProject/CipherWS/deploy/music/
```

脚本尊重已有的环境变量：你若自己设过 `AUDIO_MUSIC_PATH`，它不会覆盖。

### 方式二：手动指定任意磁盘目录

```powershell
$env:AUDIO_MUSIC_PATH = 'file:D:/music/'
# 注意：末尾的 "/" 建议保留；Windows 路径用正斜杠
```

路径支持 `classpath:`、`file:` 前缀或普通目录；`AudioServiceImpl` 会自行在末尾补 `/`。

## 四、注意事项

- **不要用 `java -jar` 裸启动 say-service 后期待音频可用**：音频已不在 classpath，
  不设 `AUDIO_MUSIC_PATH` 时 `/audio/stream` 会返回 404。请统一用 `run-services.ps1` 启动。
- **不要用 `git add -f` 强制添加**音频：`-f` 会绕过 `.gitignore`，等于把 131 MB 重新塞进历史。
- **代码区不放文档**：本目录下不再有 `README.md`（已删）。项目约定是所有说明文档
  统一放在 `docs/<日期>/` 下，避免在源码树里混入无关文件。
