# deploy/ —— 本地部署与运行

本目录把「跑起来 CipherWS 后端」所需的全部东西收在一起，**不污染系统全局环境**
（不改系统环境变量、不装 Windows 服务、不依赖 Docker）。

## 目录结构

```
deploy/
├── .tools/                     # 项目本地工具链（已 ignore）
│   ├── jdk-17/                 #   Temurin JDK 17.0.20.1（约 303 MB）
│   ├── fetch-jdk17.ps1         #   重建 JDK
│   └── dev-env.ps1             #   仅当前终端注入 JAVA_HOME
├── nacos/                      # Nacos 3.3.0-RC standalone（已 ignore，约 235 MB）
│   ├── bin/  conf/  target/    #   发行包解压后的标准结构
│   └── data/  logs/            #   运行期生成（Derby 数据、日志）
├── music/                      # 音频资源（已 ignore，约 131 MB）
│                               #   由 run-services.ps1 经 AUDIO_MUSIC_PATH 注入
├── .logs/                      # 三个后端服务的 stdout/stderr（已 ignore）
├── fetch-nacos.ps1             # 下载 + 校验 MD5 + 解压 Nacos
├── start-nacos.ps1             # 启动 Nacos（standalone，后台）
├── stop-nacos.ps1              # 停止 Nacos
├── run-services.ps1            # start / stop / status 三个后端服务
└── .user-path-backup.txt       # 本机 PATH 修改前的备份（已 ignore）
```

> **代码区不放文档**：本目录下没有 README，相关说明统一放在
> `docs/2026-10-5/` 下（即本文件与同级的另两篇）。
> 所有 `.ps1` 都是纯 ASCII，兼容 Windows PowerShell 5.1 的 ANSI 读取方式；
> 由于本机执行策略为 Restricted，统一用下面的 `-ExecutionPolicy Bypass` 形式调用。

## 端口规划

| 端口 | 进程 | 用途 |
| --- | --- | --- |
| `8080` | cipherws-gateway | **对外唯一入口**（前端 `VITE_API_BASE_URL` 指向这里） |
| `8081` | cipherws-say-service | 业务服务（名言 + 音频） |
| `8082` | cipherws-portal-service | BFF 聚合（OpenFeign 调 say） |
| `8848` | Nacos | 注册/配置中心主端口（微服务连接地址） |
| `8849` | Nacos Console | 控制台 Web UI |
| `9848` | Nacos | 客户端 gRPC |

> 控制台为什么是 **8849**：Nacos 上游默认 8080，会和网关冲突。
> 本项目在 `nacos/conf/application.properties` 里设置
> `nacos.console.port=8849`，与仓库原有的 `docker/run.sh` 端口映射保持一致。

## 音频资源（已移出版本库）

14 个音频文件（约 131 MB）已从 `server/.../resources/music/` 移出 Git，改放
**`deploy/music/`**（同样不入库）：

| | 说明 |
| --- | --- |
| 为什么 | 131 MB 会让仓库永久变重；GitHub 单文件上限 100 MB，超标即无法推送，事后删除也不缩小历史 |
| 放哪 | `deploy/music/`（仓库外），或任意磁盘目录 |
| 怎么生效 | `run-services.ps1` 启动时会自动注入 `AUDIO_MUSIC_PATH=file:<项目根>/deploy/music/` |
| 手动覆盖 | 自己设 `AUDIO_MUSIC_PATH`（如 `file:D:/music/`），脚本会尊重已有值 |
| 打包影响 | say-service 的 jar 从 **186 MB 降到 56 MB**（音频不再进 classpath） |

> 注意：因为音频不在 classpath 了，**直接用 `java -jar` 裸启动 say-service 时音频接口会 404**，
> 除非显式设置 `AUDIO_MUSIC_PATH`。建议统一用 `run-services.ps1` 启动。
> 详见 [音频资源说明.md](音频资源说明.md)。

## 启动顺序

### 1) 确保 JDK 与 Nacos 已安装

```powershell
# 在项目根目录执行（已装会跳过）
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\.tools\fetch-jdk17.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\fetch-nacos.ps1
```

### 2) 构建后端

```powershell
. .\deploy\.tools\dev-env.ps1          # 仅当前终端启用项目内 JDK 17
cd server
.\mvnw.cmd clean package               # 首次会下载依赖
cd ..
```

### 3) 启动 Nacos

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\start-nacos.ps1
```

脚本会：校验项目内 JDK 存在 → 已运行则直接返回 → 以 standalone 模式后台启动 →
轮询 8848 端口直到就绪（通常约 15~20 秒）→ 打印访问地址。
失败时会自动打印 `logs\start.out` / `logs\nacos.log` 的尾部便于排查。

> **启动方式说明**：脚本用 `javaw.exe`（无控制台窗口的 JVM）直接拉起
> `target\nacos-server.jar`，参数与 `bin\startup.cmd -m standalone` 完全等价
> （同样的 `-Dnacos.standalone` / `-Dnacos.home` / `-Dloader.path` /
> `--spring.config.additional-location`，Java 9+ 的 `--add-opens` 也一并加上）。
> 之所以不直接调 `startup.cmd`：它会在控制台窗口里跑，**窗口被关掉就会带走 Nacos 进程**
> （本机实测发生过一次：Nacos 在运行 30 分钟后无声退出，日志里没有优雅关闭记录、
> 没有 OOM 堆转储、系统事件日志也无相关条目，符合"控制台被关导致进程树终止"的特征）。
> `javaw` 没有可被关闭的窗口，因此更稳。仍想用官方脚本时用 `-Foreground` 参数。

### 4) 启动三个服务并验证

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\run-services.ps1 -Action start
# 查看状态
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\run-services.ps1 -Action status
```

验证（全部实测通过）：

```powershell
# 网关 -> say 服务
curl.exe "http://127.0.0.1:8080/say/saying?id=1"
# {"success":true,...,"data":{"id":1,"saying":"青年时种下什么，老年时就收获什么。","person":"易卜生"}}

# 网关 -> portal -> OpenFeign -> Nacos -> say
curl.exe "http://127.0.0.1:8080/portal/say/2"

# 音频 Range 分段（期望 206）
curl.exe -r 0-9 -o NUL -w "%{http_code}`n" "http://127.0.0.1:8080/audio/stream?audio=HOYO-MiX%20-%20Da%20Capo.mp3"
```

### 5) 关闭

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\run-services.ps1 -Action stop
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\stop-nacos.ps1
```

`stop-nacos.ps1` 优先按**占用 8848 端口的进程**定位，其次按命令行匹配
`nacos-server.jar`，因此不会误杀其他 java 进程（如三个业务服务）。

## ⚠️ 鉴权：本地开发已关闭（重要）

`nacos/conf/application.properties` 中：

```properties
nacos.core.auth.enabled=false
nacos.core.auth.admin.enabled=false
nacos.core.auth.console.enabled=false
```

**为什么关**：本机部署的是 Nacos **3.3.0-RC**（一个 RC 版本），其管理员引导流程异常——
在**已清空 `data/` 的全新状态**下：

- `POST /nacos/v3/auth/user/admin` 返回 `409 have admin user cannot use it`
  （或返回一个随机密码，但该密码随后无法登录）；
- 任何 用户名/密码 组合调用 `POST /nacos/v3/auth/user/login` 都返回
  `User not found! Please check user exist or password is right!`，且**不写入 `logs/core-auth.log`**；
- 结果是微服务启动时注册被拒：`ErrCode:403 ... User not found`，
  Spring Boot 应用直接启动失败。

关闭鉴权后，三个服务注册与网关路由**均已实测通过**（见上文验证命令）。

**若要恢复鉴权**（例如换用稳定版 Nacos 3.2.x 后）：

1. 把上面三项改回 `true`；
2. 打开 `http://127.0.0.1:8849/` 按控制台引导初始化管理员密码；
3. 让服务端配置与之一致——`server/*/src/main/resources/application.yml` 里当前硬编码为
   `username: nacos` / `password: 1357924680bb`，也可用环境变量覆盖：
   `NACOS_USERNAME` / `NACOS_PASSWORD`。

> 注：`startup.cmd` 无论鉴权开关如何，都要求
> `nacos.core.auth.server.identity.key/value` 与
> `nacos.plugin.auth.nacos.token.secret.key` 非空，本仓库已按 `docker/run.sh`
> 的同源取值配好（token secret 为解码后 ≥32 字节的合法 Base64）。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `无法加载文件 ... 禁止运行脚本` | 本机执行策略为 Restricted，用 `-ExecutionPolicy Bypass`，或 `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` |
| 服务启动报 `ErrCode:403` | 鉴权被打开了但凭据不对，见上文「鉴权」一节 |
| 网关返回 503 | Nacos 没起或服务未注册；先 `run-services.ps1 -Action status`，再看 `.logs\*.out.log` 里的 `REGISTER-SERVICE` 行 |
| `start-nacos.ps1` 报端口已占用 | 先跑 `stop-nacos.ps1`；该脚本按端口占用者定位进程 |
| 控制台打不开 | 确认 `nacos.console.port=8849`（上游默认 8080 与网关冲突） |
