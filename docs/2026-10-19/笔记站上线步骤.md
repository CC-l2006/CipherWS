# 笔记站上线步骤（note.cipherws.icu）

> 对应配置：`deploy/nginx/cipherws.conf`（server 块 ③）
> 对应前端：`frontend/note`（构建到 `frontend/note/dist`）
> 日期：2026-10-19

## 一、链路长这样

```
浏览器
  │  https://note.cipherws.icu/          → nginx → 127.0.0.1:8002（node 提供的 SPA）
  │  https://note.cipherws.icu/api/**    → nginx → 127.0.0.1:8083（note-gateway）
  │  https://note.cipherws.icu/uploads/**→ nginx → 127.0.0.1:8083（头像，网关放行不鉴权）
  │
  └─ note-gateway(8083) ──Nacos──> note-user(8084) / note-core(8085) /
                                    note-ai(8086) / note-admin(8087)  ──> MySQL
```

端口沿用 `frontend/` 的「8000 + 序号」约定：main=8000 / train=8001 / **note=8002**。

**为什么 `/api` 不交给 node 转发**：node 只是静态服务器，没有鉴权能力。
JWT 校验、身份注入（`X-User-Id`）与分流都在网关里，让 node 转发等于绕过网关。

## 二、服务器上要跑的东西

| 进程 | 端口 | 说明 |
| --- | --- | --- |
| `cipherws-web-note` | 8002 | `node server.js --app note`，只服务 `frontend/note/dist` |
| `note-gateway` | 8083 | 网关，唯一对外的后端入口 |
| `note-user/core/ai/admin` | 8084–8087 | 四个业务服务，**不要对公网开放** |
| MySQL / Nacos | 3306 / 8848 | 已有 |

### 一个 systemd 单元示例（note 前端）

```ini
# /etc/systemd/system/cipherws-web-note.service
[Unit]
Description=CipherWS 池禾笔记 frontend (node static server)
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/cipherws/frontend
# 注意：uploads 目录是相对**进程工作目录**的，所以工作目录决定头像落在哪
ExecStart=/usr/bin/node server.js --app note
Restart=on-failure
RestartSec=3
# 生产环境建议显式指定上传目录，避免和 main 站点混在一起
Environment=NOTE_UPLOAD_DIR=/opt/cipherws/uploads

[Install]
WantedBy=multi-user.target
```

后端四个服务同样各配一个 unit，都要带：
`DB_PASSWORD`、`NACOS_SERVER_ADDR`、`NOTE_JWT_SECRET`（**网关与用户服务必须一致**）。
邮件相关的 4 个变量见 `docs/2026-10-19/邮箱验证码与头像上传.md`。

## 三、上线顺序

```bash
# 1) 拉代码并构建
cd /opt/cipherws
git pull
cd frontend/note && npm ci && npm run build && cd ../..

# 2) 后端打包（四个服务 + 网关）
cd server
./mvnw -DskipTests package
# 各自拷到运行目录，或用 systemd 直接指向 target/xxx.jar

# 3) 起服务：先 4 个业务服务，最后网关
sudo systemctl restart note-user note-core note-ai note-admin
sudo systemctl restart note-gateway
sudo systemctl restart cipherws-web-note

# 4) nginx
sudo nginx -t && sudo systemctl reload nginx

# 5) 验证
curl -I https://note.cipherws.icu/                       # 200，且 <title>池禾笔记</title>
curl -s https://note.cipherws.icu/api/notes              # 401「未登录」= 网关正常
curl -s https://note.cipherws.icu/actuator/health        # 走的是 8002，会 404，正常
curl -s http://127.0.0.1:8083/actuator/health            # 网关健康，应 UP
```

## 四、HTTPS 必须单独签证书

⚠️ **现有的 `cipherws.icu` 证书只覆盖 `cipherws.icu` 与 `www.cipherws.icu`，
不包含 `note.cipherws.icu`。** 直接拿它给这个子域名用，浏览器会报
`NET::ERR_CERT_COMMON_NAME_INVALID`，等于没有 HTTPS。

```bash
# 单独给这个子域名签（HTTP-01，走已经预留好的 ACME 目录）
sudo certbot certonly --webroot -w /var/www/certbot \
     -d note.cipherws.icu \
     --deploy-hook "systemctl reload nginx"

# 或者一次签通配符，以后加子域名不用再签（必须 DNS-01，要去域名解析加 TXT）
sudo certbot certonly --manual --preferred-challenges dns \
     -d cipherws.icu -d '*.cipherws.icu'
```

签好后把 `deploy/nginx/cipherws.conf` 里注释掉的 HTTPS 段打开，
证书路径改到实际位置（`/etc/letsencrypt/live/note.cipherws.icu/fullchain.pem`），
再把 80 端口那段改成 301 跳转（照主站 ① 的写法）。

## 六、更新与启动脚本

**前端**：`deploy/update-frontend.sh` 已支持 `--site note`（`--site all` 会把三个站点一起更新）。

```bash
./deploy/update-frontend.sh --site note     # 只更新笔记站
./deploy/update-frontend.sh                 # 三个站点全量
```

note **不需要重启进程** —— `server.js` 每次请求都读磁盘（`statSync` + `createReadStream`），
产物落盘即生效。脚本会用 `NOTE_PORT`（默认 8002）探活，进程没起时会提示怎么起。
脚本里 nginx 探活的期望值也改对了：main 与 note 的 80 端口现在是 **301**，
train 仍是 200，不再一律要求 200（以前每次都会误报一条警告）。

**后端**：在笔记本上用下面任一入口起全部 8 个服务（4 个主站 + 4 个笔记 + 2 个网关）

```powershell
# 推荐：带前置检查、状态表、端点探活
powershell -NoProfile -ExecutionPolicy Bypass -File .\docs\startupCommand\Backend\启动后端.ps1

# 或者只驱动服务本身
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\run-services.ps1 -Action start
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\run-services.ps1 -Action status
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\run-services.ps1 -Action stop
```

启动顺序：`say → portal → cipherws-gateway`，然后 `note-user → note-core → note-ai →
note-admin → note-gateway`，网关都在各自那组的最后。

笔记的 5 个服务需要的密钥从 **`deploy/note.env.local`** 读取（`.gitignore` 的
`*.local` 规则已忽略），模板是 `deploy/note.env.example`。启动脚本还会顺带加载
`deploy/mail.env.local`，所以邮件配置只需要维护一份。

> `启动后端.ps1` 的内容必须是**纯 ASCII**：Windows PowerShell 5.1 按 ANSI 读 .ps1，
> 文件里出现中文会变成乱码（文件名是中文没问题）。改动时别破坏这一点。
