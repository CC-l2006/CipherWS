# 邮箱验证码与头像上传

> 对应代码：`server/note-user-service`（`MailService`、`AvatarService`、`UserServiceImpl`）
> 对应前端：`frontend/note/src/views/Profile.vue`
> 日期：2026-10-19

## 一、验证码是怎么发出去的

整条链路其实很朴素：

```
前端点「发送验证码」
   → POST /api/user/email/code
   → UserServiceImpl.issueCode()  生成 6 位码、存内存、60 秒频控
   → MailService.sendCode()
   → JavaMailSender.send()        ← 这里才真正走 SMTP
   → 你的邮箱
```

**关键点：验证码不是「发给前端」的，是发给邮箱的。** 后端只把码存在自己内存里，
收到 `PUT /api/user/email` 时再比对。前端拿不到码（除非开了演示开关，见下）。

### 1. 为什么默认不发信

`MailService.isEnabled()` 要同时满足三个条件：

1. `NOTE_MAIL_ENABLED=true`（`note.mail.enabled`）
2. Spring 容器里存在 `JavaMailSender` —— 它只有在 `spring.mail.host` 配置了才会创建
3. `spring.mail.username` 非空

任何一个不满足，就退化成**把验证码打到服务端日志**：

```
WARN ... [note-user] 未配置 SMTP，验证码只写日志。to=xxx@qq.com purpose=bind code=123456
```

这样本地开发不用先去申请邮箱授权码也能把「找回密码 / 绑定邮箱」跑通。
（`application.yml` 里故意不写 `spring.mail.host`，就是为了让这个 bean 不存在 ——
写了空串反而会创建出一个连不上的 JavaMailSender，把 `/actuator/health` 拉成 DOWN。）

### 2. 真要发信：以 QQ 邮箱为例

**第一步：拿授权码（不是登录密码）**

QQ 邮箱 → 设置 → 账户 → 「POP3/IMAP/SMTP 服务」→ 开启 → 生成授权码（16 位）。
163、Gmail 同样有类似机制；Gmail 需要开两步验证后生成「应用专用密码」。

**第二步：设环境变量再启动**

```bash
export SPRING_MAIL_HOST=smtp.qq.com
export SPRING_MAIL_PORT=465
export SPRING_MAIL_USERNAME=你的QQ号@qq.com
export SPRING_MAIL_PASSWORD=刚才拿到的16位授权码
export NOTE_MAIL_ENABLED=true
export MAIL_FROM=你的QQ号@qq.com          # 留空则用 USERNAME
export NOTE_EXPOSE_CODE=false             # 配了真邮箱就别再回传验证码

java -jar note-user-service.jar
```

> 用 `SPRING_MAIL_*` 这个前缀是因为 Spring Boot 会自动把环境变量映射成
> `spring.mail.*`，不需要改 `application.yml`。

常见邮箱的参数：

| 邮箱 | host | 端口 | 说明 |
| --- | --- | --- | --- |
| QQ | `smtp.qq.com` | 465 | SSL；必须用授权码 |
| 163 | `smtp.163.com` | 465 | SSL；必须用授权码 |
| Gmail | `smtp.gmail.com` | 465 | SSL；需应用专用密码 |
| 企业微信/阿里云邮件推送 | 各自控制台给 | 通常 465 或 587 | 量大时用这类服务 |

**587 端口（STARTTLS）**：把 `application.yml` 里的 `ssl.enable` 换成
`starttls.enable: true` 即可。很多云服务器封了出站 25，465/587 一般没事。

**第三步：验证**

```bash
curl -X POST http://127.0.0.1:8084/user/email/code \
     -H 'X-User-Id: 2' -H 'Content-Type: application/json' \
     -d '{"email":"你要收信的地址@example.com"}'
```

返回值里的 `code` 应该变成 `null`（因为配了真邮箱就不回传了），
邮箱里应该收到一封标题为「【CipherWS 笔记】绑定邮箱验证码」的邮件。

### 3. 排查表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `AuthenticationFailedException: 535` + 提示「服务器邮箱授权码已失效」 | ①（最常见）**授权码在邮箱后台重新生成过**，旧码立即作废；② 用了登录密码而不是授权码；③ 该邮箱没开启 SMTP 服务 | 去邮箱后台生成**新**授权码，更新 `deploy/mail.env.local` 的 `SPRING_MAIL_PASSWORD`，重启服务。注意：重新生成后旧码**不会**继续可用，必须同步替换 |
| 535 但授权码确认是对的 | 登录过于频繁 / 账号被临时限制 | 等 10 分钟再试；QQ 后台看是否有登录异常提示 |
| `Could not connect to SMTP host` | 出站端口被封 / host 写错 | 换 587 + STARTTLS，检查安全组 |
| `554 被识别为垃圾邮件` | 发件内容太像营销 / 频率太高 | 换独立发件账号，别用主邮箱 |
| 收不到但日志说已发送 | 进了垃圾箱 / 收件方拦截 | 查垃圾箱，加白名单 |
| 返回 `code` 有值 | `NOTE_MAIL_ENABLED` 没开或 `host` 没生效 | 确认三个条件都满足 |
| **配好邮箱后 `/actuator/health` 要十几秒** | `MailHealthIndicator` 每次心跳都**新建一条 SMTP 连接**去测活，实测单次 **11.9 秒** | yml 里已设 `management.health.mail.enabled: false` |

> 最后一条是实测踩到的：配了 `SPRING_MAIL_HOST` 之后 Spring 会自动注册
> `MailHealthIndicator`，日志里会看到 `took 11957ms to respond`。
> 后果是 nginx / k8s 的探活直接超时，服务明明正常却显示不健康。
> 关掉之后健康检查从 11.9s 回到 **0.01–0.5s**。
> 另外「邮件暂时发不出去」也不该把整个服务判成 DOWN —— 用户照样能读写笔记。

### 4. 生产环境的几条硬要求

1. **`NOTE_EXPOSE_CODE=false`**。默认是 `true`（为了演示），开了它任何人都能
   拿到验证码直接重置密码。
2. **别用主邮箱发信**。被投诉或触发风控会连累主邮箱，注册个专用发件箱。
3. **60 秒频控 + 5 次试错上限**已经内置，但都是**单实例内存态**。多实例部署时
   必须换成 Redis，否则在 A 实例发的码到 B 实例校验不过；同时要加**按用户/IP 的
   总量限制**，现在只按邮箱限制，理论上可以用不同邮箱刷接口。
4. 验证码只存内存，重启就失效 —— 这是有意的（比落库更安全），但重启会让正在
   验证的用户需要重新获取。

## 二、头像上传

### 1. 校验顺序（每一层都不能省）

| 层 | 拦什么 | 为什么 |
| --- | --- | --- |
| 前端 | 类型白名单、2MB | 少传一趟，改善体验 |
| `spring.servlet.multipart` | 单文件 2MB / 请求 3MB | 防止把大文件读进内存 |
| `AvatarService` 魔数 | 只认 PNG/JPEG/WebP 的文件头 | `Content-Type` 是客户端填的，可伪造 |
| `AvatarService` 解码 | ImageIO 真解一次 + 边长 ≤4096 | 文件头对、内容垃圾的文件 |
| 文件名 | 服务端生成 | 客户端文件名可能含 `../../`，能写到任意路径 |

### 2. 文件放在哪、怎么访问

```yaml
note:
  upload:
    dir: ${NOTE_UPLOAD_DIR:./uploads}   # 相对进程工作目录
    max-bytes: 2097152
```

落盘路径：`uploads/avatar/<用户id>-<16位随机串>.png`。

访问路径：`GET /uploads/avatar/xxx.png`

- **开发**：Vite 把 `/uploads` 也代理到 8083（见 `vite.config.mjs`），否则 `<img>` 会 404
- **生产**：网关有一条 `Path=/uploads/**` 路由，**不剥前缀**、**不校验 token**，
  原样转给 note-user-service，由 `WebConfig` 的资源处理器吐文件

> 为什么不放在 `/api/**` 下面？因为 `<img src>` 发不了 `Authorization` 头，
> 走需要鉴权的路由只会得到一片 401。安全性靠文件名不可枚举（用户 id + 16 位随机串），
> 而不是鉴权 —— 这属于「知道 URL 就能看」的取舍，头像本来也不是敏感数据。

生产环境也可以让 nginx 直接指向这个目录，少一层 Java 转发：

```nginx
location /uploads/ {
    alias /opt/cipherws/server/uploads/;
    expires 30d;
    add_header Cache-Control "public";
}
```

### 3. 换头像时旧文件会删掉

`uploadAvatar` 里先落新文件、更新数据库，再删旧文件。只删 `/uploads/avatar/`
下自己管理的文件；如果用户头像是外链（理论上不该出现），跳过不删。
删失败只记一条 warn，不影响上传结果 —— 最坏情况是留个孤儿文件。

## 三、这次实际验证了什么

在真实 MySQL 8.0.46 + 真实服务上跑过：

- 邮箱换绑全流程：发码 → 错码被拒 → 正确码换绑成功 → 同一个码不能重复用
- 60 秒频控（同一邮箱连发第二次被拦，提示剩余秒数）
- 验证码试错 5 次后锁定（第 6 次提示「错误次数过多，请重新获取」）
- 用途隔离：找回密码的码不能用来绑邮箱
- 注册流程（2026-10-20 新增）：`purpose=register` 发码 → 错码被拒 → 正确码建号 →
  同邮箱再发注册码被拒（「该邮箱已注册，请直接登录」）→ 用邮箱登录成功
- 注册时账号名由邮箱前缀自动生成（`zhangsan@qq.com` → `zhangsan`），不再要求用户名唯一
- 绑定已被占用的邮箱被拒；绑定自己当前邮箱被拒
- 头像上传：真实 PNG 上传成功，`GET /uploads/...` 返回 `image/png` 与正确字节数
- 伪造的「图片」（文本内容 + `image/png` 头）被魔数校验拦下
- 3MB 文件被拒（`MaxUploadSizeExceededException` 已转成友好文案）
- `PUT /user/profile` 传 `email` 无效 —— 邮箱只能走验码流程
- 外链头像被拒
- 前端（mock 模式）用 CDP 驱动实测：上传头像 → 头像与侧栏同步更新 → 邮箱换绑成功，
  **0 控制台错误**

**真实 SMTP 发信已验证**（QQ 邮箱 `smtp.qq.com:465` + 授权码）：

- `POST /user/email/code` 返回 `success: true`、`code: null`、`hint: 验证码已发送至 xxx@qq.com`
- 服务端日志：`[note-user] 验证码邮件已发送 to=xxx@qq.com purpose=bind`
- 首次发送耗时约 4.7 秒（含 SMTP 握手），之后约 1.7 秒
- **连不上时会明确报错**，并回滚内存里的验证码与 60 秒频控，可以立刻重试
- 哪怕 `NOTE_EXPOSE_CODE=true`，只要真发信模式生效，响应里也不会带 `code`

配置放在 `deploy/mail.env.local`（被 `.gitignore` 的 `*.local` 规则忽略，不会误提交），
可以照 `deploy/mail.env.example` 这个模板改。
