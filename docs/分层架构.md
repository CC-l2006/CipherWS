## L1 用户接入层

| 项 | 内容 |
|---|---|
| 使用者 | 访客、答辩评委、开发者本人 |
| 终端 | PC 浏览器（主用 Microsoft Edge）、手机浏览器 |
| 协议 | HTTP（当前，IP 访问）→ HTTPS（域名备案通过后） |
| 入口 | 公网域名 / 公网 IP |

**该层关注**：首屏加载速度、响应式布局（移动端适配）、资源体积（首屏 JS 约 450KB，gzip 后约 128KB）。

---

## L2 网络接入与路由层

| 组件 | 职责 | 当前状态 |
|---|---|---|
| DNS | 域名 → 服务器 IP 解析（`@` 与 `design` 两条 A 记录） | 待备案 |
| 阿里云安全组 | 端口级访问控制（外层防火墙） | 8000 已放行 |
| 系统防火墙 | 主机级访问控制（内层） | — |
| **分流组件** | 按 `Host` 头把请求分发到不同站点 | 阶段一：多端口；阶段二：nginx |

**该层关注**：跨域（CORS）收敛、HTTPS 终结、后端端口不对外暴露。

> 阶段一没有 nginx，用「不同端口对应不同站点」替代域名分流；这是过渡方案，不是终态。

## L3 前端应用层

### L3a 主站（`cipherws.icu`）

| 项 | 内容 |
|---|---|
| 技术栈 | Vue 3 + Vite 5 + vue-router 4 |
| 布局 | `DefaultLayout`：`AppHeader` → `NavMenu` → `main` → `AppFooter` |
| 页面 | `/` 首页（每日一句）、`/link` 链接页 |
| 全局能力 | 开场加载动画（Lottie）、页面左右滑动切换、悬浮控件（设置/音乐） |
| 构建产物 | `frontend/dist/`（含 hash 的静态资源） |

### L3b 子系统（`design.cipherws.icu`）

| 项 | 内容 |
|---|---|
| 定位 | 独立开发、独立部署的子系统 |
| 可复用 | 布局骨架、`meta.depth` 滑动动画方案、开场动画防挂死 loader、`server.js` |
| 待定 | 技术栈是否沿用 Vue；目录为独立仓库还是本仓 `design/` |

**该层关注**：SPA 路由回退（`try_files` / 服务端 fallback，否则 `/link` 刷新 404）、构建时环境变量注入（`VITE_API_BASE_URL`）、静态资源缓存策略（hash 文件长缓存、`index.html` 不缓存）。

## L4 后端服务层

| 项 | 内容 |
|---|---|
| 技术栈 | Spring Boot 3.5.16 + JDK 17 + Maven |
| 架构形态 | **模块化单体**（单 jar / 单进程 / 单端口） |
| 现有接口 | `GET /say/saying?id=N` → 返回 `Result` 包装 |
| 包结构 | `common`（公共）/ `modules.say`（主站）/ `modules.design`（子系统） |
| 对外端口 | 8080（接入 nginx 后应只监听 `127.0.0.1`） |

**该层关注**：模块边界清晰（将来可整体拆出 `design` 模块独立成服务）、CORS 白名单收紧、统一响应结构、异常处理。

## L5 数据层

| 项 | 内容 |
|---|---|
| 现状 | **无数据库**。名言数据来自 `saying.json` 静态文件，通过 `SayingComponent` 读取 |
| 规划 | 引入关系型数据库（MySQL / PostgreSQL） |
| 关键约束 | 若子系统与主站共用库，**必须先划分表归属**：哪张表归谁写、谁只读 |

## L6 基础设施与运行环境层

### 云端（阿里云 ECS · Ubuntu · `47.104.253.198`）

| 组件 | 说明 |
|---|---|
| 运行托管 | systemd（开机自启、崩溃自动重启） |
| 静态服务 | Node `server.js`（零依赖，含 SPA 回退 / gzip / 缓存策略） |
| 应用服务 | Spring Boot jar |
| 规划 | 备案通过后引入 nginx + HTTPS 证书 |

### 本地（笔记本）

| 角色 | 说明 |
|---|---|
| 开发 | 编码、`npm run dev` 预览（Vite Dev Server） |
| 构建 | 可选；**正式产物统一在服务器上构建**，避免 Node 版本差异 |
| 版本管理 | Git 本地仓库 → 推送 GitHub → 服务器拉取 |

**该层关注**：本地不承担对外服务（家庭宽带动态 IP + 内网暴露风险）；环境一致性优先在云端保证。

## 横切关注点（贯穿各层）

| 关注点 | 现状 | 待办 |
|---|---|---|
| 跨域 CORS | 后端 `allowedOriginPatterns("*")` + `allowCredentials(true)` | **需收紧为显式白名单**；或改由 nginx 同源反代彻底规避 |
| HTTPS | 无（IP 无法申请免费证书） | 备案后为两个域名各配证书 |
| 日志 | systemd journal | 规划：应用日志落盘 + 轮转 |
| 配置管理 | 前端 `.env.production`（构建时注入）<br>后端 `application.properties` | 敏感配置不入库 |
| 错误监控 | 无 | 规划：前端错误上报、后端异常日志 |
| 部署流程 | 手工 `git pull` + `npm run build` + `systemctl restart` | 规划：脚本化 |
| 安全 | 后端端口对外开放 | 接入 nginx 后收敛为仅本机访问 |

## 一次请求的完整链路（当前阶段）

```
① 浏览器访问 http://47.104.253.198:8000/
② 阿里云安全组校验 8000 端口 → 放行
③ systemd 托管的 node server.js 收到请求
④ 命中 dist/index.html（SPA 回退已兜底任意前端路由）
⑤ 浏览器加载 JS/CSS 资源（hash 文件走长缓存）
⑥ 页面请求 GET /say/saying?id=N
⑦ 浏览器直连 http://47.104.253.198:8080（跨域，依赖后端 CORS 放行）
⑧ Spring Boot SayController → SayService → SayingComponent 读取 saying.json
⑨ 返回 Result 包装的 JSON → 前端渲染
```

**阶段二（nginx 接入后）链路变化**：第 ③ 步变为 nginx，第 ⑥⑦ 步变为**同源**请求 `/say/saying`，由 nginx 反代到 `127.0.0.1:8080`，**跨域问题消失**，且后端 8080 不再对外暴露。
