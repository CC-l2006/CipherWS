# CipherWS 项目架构文档

> 最后更新：2026-10-20
> 适用范围：本仓库全部代码（`frontend/`、`server/`、`deploy/`）

---

## 一、项目概览

CipherWS 是一个**个人站点 + 两个子项目**的组合，共三个可独立访问的站点：

| 站点 | 域名 | 内容 |
| --- | --- | --- |
| 主站 | `cipherws.icu` / `www.cipherws.icu` | 个人主页、每日一句、音乐播放器、友链 |
| 云间列车 | `train.cipherws.icu` | WebGL2 渲染的独立小项目 |
| 池禾笔记 | `note.cipherws.icu` | 笔记系统：标签、回收站、AI 摘要、后台管理 |

**核心约束**：前端在云上，后端在本地笔记本，中间靠樱花内网穿透连起来。

| | 服务器 A：阿里云 ECS | 服务器 B：本地笔记本 |
| --- | --- | --- |
| 角色 | 公网入口、前端静态资源 | 全部后端微服务、数据库、注册中心 |
| 系统 | Ubuntu 24.04 LTS | Windows |
| 公网 IP | `47.104.253.198` | 无（靠隧道） |
| 运行 | nginx（80/443）、一个 node 静态服务（8000） | Nacos、MySQL、8 个 Spring Boot 进程、frpc |
| 成本 | 常驻云主机 | 断开即后端不可用 |

这样拆的理由：笔记本算力和已装环境（JDK / MySQL / Nacos）直接复用，云主机只承担静态分发与 TLS 终结，最省配置。代价是**笔记本关机 / 隧道掉线时接口全挂**（页面仍能打开）。

## 二、总体架构图

```
                          ┌─────────────────────────────┐
   浏览器 ──── HTTPS ────► │  nginx (ECS)  80 / 443      │
                          │  · cipherws.icu             │
                          │  · train.cipherws.icu       │
                          │  · note.cipherws.icu        │
                          └──────┬───────────────┬──────┘
                                 │               │
                    静态文件      │               │  /say/  /audio/  /portal/
              (train / note 的   │               │  /api/  /uploads/
               dist 直接读盘)    │               │
                                 ▼               ▼
                       dist 目录           樱花隧道 frp-box.com:64456
                     （nginx 自己吐）              │
                                                  ▼
   ┌─────────────────────────── 笔记本（后端）────────────────────────────┐
   │                                                                      │
   │  frpc ──► cipherws-gateway :8080 ──┬──► cipherws-say-service   :8081 │
   │                                     │    （名言 + 音频流）             │
   │                                     ├──► cipherws-portal-service :8082│
   │                                     │    （Feign 聚合）               │
   │                                     ├──► note-gateway          :8083 │
   │                                     │     │                          │
   │                                     │     ├─► note-user-service  :8084│
   │                                     │     ├─► note-core-service  :8085│
   │                                     │     ├─► note-ai-service    :8086│
   │                                     │     └─► note-admin-service :8087│
   │                                     │                                │
   │                                     └──► /uploads/** 也交给 note-gateway│
   │                                                                      │
   │  Nacos :8848 / :8849 / :9848  ◄── 8 个服务全部注册在这里              │
   │  MySQL :3306  库 CipherWS（9 张表）◄── note-* 四个服务（MyBatis）      │
   └──────────────────────────────────────────────────────────────────────┘
```

**关键设计：只穿透一个端口（8080）**

笔记本只把 `cipherws-gateway:8080` 通过樱花暴露出去。笔记站的接口不是走第二条隧道，而是由 `cipherws-gateway` 加了两条路由（`/api/**`、`/uploads/**` → `lb://note-gateway`）**转发**给 `note-gateway`。

于是 nginx 侧只需要认一个后端地址，隧道多一条都不用配。

## 三、服务器 A：阿里云 ECS

### 3.1 基础信息

| 项 | 值 |
| --- | --- |
| 公网 IP | `47.104.253.198` |
| 系统 | Ubuntu 24.04 LTS |
| nginx | 1.24.0（**注意**：不支持 `http2 on;`，只能写 `listen 443 ssl http2;`） |
| 代码目录 | `/opt/cipherws`（git 仓库，分支 `main`） |
| 上传目录 | `/opt/cipherws/uploads`（头像） |
| nginx 配置 | `/etc/nginx/conf.d/cipherws.conf`（仓库内 `deploy/nginx/cipherws.conf`） |
| 证书目录 | `/etc/nginx/ssl/`（属主 root，目录 700，私钥 600） |
| ACME 目录 | `/var/www/certbot`（续期用） |

### 3.2 nginx 的四个 server 块

| # | 监听 | server_name | 作用 |
| --- | --- | --- | --- |
| ①a | 80 | `cipherws.icu` `www.cipherws.icu` | 只做 ACME 挑战 + 301 跳 HTTPS |
| ①b | 443 | 同上 | 静态页反代 node `127.0.0.1:8000`；`/say/` `/audio/` `/portal/` 反代隧道 |
| ② | 80 | `train.cipherws.icu` | 直接托管 `frontend/train/dist`（无进程） |
| ③a | 80 | `note.cipherws.icu` | 只做 ACME 挑战 + 301 跳 HTTPS |
| ③b | 443 | `note.cipherws.icu` | 托管 `frontend/note/dist`（无进程）；`/api/` `/uploads/` 反代隧道 |

两个 upstream：

```nginx
upstream cipherws_frontend { server 127.0.0.1:8000; keepalive 16; }
upstream cipherws_backend  { server frp-box.com:64456; keepalive 16; }   # 樱花隧道
```

> 换隧道地址**不要手改**，用 `sudo bash deploy/update-backend-address.sh 新域名:端口`。
> 地址在配置里一共出现 **9 处**（upstream 1 处 + 4 组 location 各自的 Host 与 SNI），
> 漏一处就会出现「连上了但 SNI 还是老域名」这种很难查的错。

### 3.3 三个站点的托管方式

| 站点 | 托管方式 | 原因 |
| --- | --- | --- |
| main | node `server.js --app main`，systemd 单元 `cipherws-web`，监听 8000 | 需要给 `/` 做 history 回退，历史上就这么起的 |
| train | nginx 直读 `dist` | 纯静态，没有后端调用 |
| note | nginx 直读 `dist` | 纯静态 + 接口走 nginx 反代，不需要 node 进程 |

`frontend/server.js` 是一个极简静态服务器（`fs.statSync` + `createReadStream`，**每次请求读磁盘**），所以重建 `dist` 后无需重启——产物落盘即生效。

### 3.4 证书

两张**独立签发**的证书，互不覆盖：

```
/etc/nginx/ssl/cipherws.icu.pem        + .key     覆盖 cipherws.icu、www.cipherws.icu
/etc/nginx/ssl/note.cipherws.icu.pem   + .key     覆盖 note.cipherws.icu、www.note.cipherws.icu
```

- 都是 90 天 DV 证书，**到期需手动更换**（换文件 + `systemctl reload nginx`）。
- `train.cipherws.icu` 目前仍是纯 HTTP，没有证书。
- 校验能否配对（两行 MD5 必须一致）：

```bash
sudo openssl x509 -in /etc/nginx/ssl/note.cipherws.icu.pem -noout -modulus | openssl md5
sudo openssl rsa  -in /etc/nginx/ssl/note.cipherws.icu.key -noout -modulus | openssl md5
```

- 校验域名与有效期：

```bash
sudo openssl x509 -in /etc/nginx/ssl/note.cipherws.icu.pem -noout -subject -dates -ext subjectAltName
```

## 四、服务器 B：本地笔记本

### 4.1 基础信息

| 项 | 值 |
| --- | --- |
| 系统 | Windows |
| Google Chrome / Edge | 仅用于前端调试 |
| JDK | 17，**项目内自带**于 `deploy/.tools/jdk-17`（不污染系统环境变量） |
| Node | 20.20.2 / npm 10.8.2 |
| Maven | 用仓库自带 wrapper `server/mvnw.cmd`，无需全局安装 |
| Nacos | 3.3.0-RC，`deploy/nacos`（standalone，非 Docker） |
| MySQL | 8.0.46，服务名 `MySQL80`，端口 3306 |

### 4.2 八个微服务

全部注册到本机 Nacos，端口刻意避开 8000–8002（前端）与 8848/8849（Nacos）：

| 端口 | 模块 | 职责 | 数据层 |
| --- | --- | --- | --- |
| 8080 | `cipherws-gateway` | 主站网关，唯一对外入口 | — |
| 8081 | `cipherws-say-service` | 每日一句、音频流（Range 分段） | 读 `saying.json` |
| 8082 | `cipherws-portal-service` | BFF 聚合，OpenFeign 调 say | — |
| 8083 | `note-gateway` | 笔记网关：校验 JWT、注入身份、按路径分流 | — |
| 8084 | `note-user-service` | 邮箱注册（验证码）/ 邮箱登录 / 资料 / 头像 / 改密 | MyBatis → MySQL |
| 8085 | `note-core-service` | 笔记 CRUD、草稿、回收站、标签 | MyBatis → MySQL |
| 8086 | `note-ai-service` | AI 摘要（OpenAI 兼容接口）、额度扣减 | MyBatis → MySQL |
| 8087 | `note-admin-service` | 用户管理、巡检、AI 参数、公告、日志、统计 | MyBatis → MySQL |

启动顺序：`say → portal → cipherws-gateway`，然后 `note-user → note-core → note-ai → note-admin → note-gateway`。网关在各自那组的最后。

### 4.3 Nacos

```
地址   127.0.0.1:8848   主端口（服务注册/配置）
       127.0.0.1:9848   客户端 gRPC
       127.0.0.1:8849   控制台 Web UI（上游默认 8080，与网关冲突，故改到 8849）
```

本机**鉴权是关闭的**（`nacos.core.auth.enabled=false`），所以配置里的账号密码填什么都行。启用鉴权后必须补 `NACOS_USERNAME` / `NACOS_PASSWORD`。

### 4.4 MySQL

```
库名    CipherWS          （Linux 下库名区分大小写，连接串必须一致）
字符集  utf8mb4 / utf8mb4_0900_ai_ci
表      9 张，见第七节
账号    root
```

> 导入脚本已自带 `CREATE DATABASE` + `USE` + `SET NAMES utf8mb4`，
> 直接用 `mysql -u root -p < server/sql/note-schema.sql` 即可，不需要先建库。
> 里面的中文默认值（如 `title` 的 `'无标题笔记'`）必须靠 `SET NAMES utf8mb4` 才不会被判非法。

### 4.5 樱花内网穿透（SakuraFrp）

```
隧道    本地 127.0.0.1:8080  →  公网 frp-box.com:64456
```

- frpc 客户端在**笔记本**上跑，断线重连后公网端口可能变化。
- 隧道地址变了就跑一次 `sudo bash deploy/update-backend-address.sh 新地址`（在 ECS 上执行）。
- 笔记站的接口复用这条隧道，**不需要第二条**。

**为什么笔记系统用 MyBatis 而不是 JPA**：动态条件多（关键词、标签、日期范围、分页），
SQL 放 XML 里比拼 Criteria 直观；而且答辩时每条 SQL 都能指着讲。
`cipherws-say-service` 那边没引入数据库，`note-*` 四个服务用的是同一套 MyBatis 配置。

## 六、请求链路（四条）

### 6.1 打开页面（不涉及后端）

```
浏览器 → nginx:443 → 读 /opt/cipherws/frontend/<站点>/dist/index.html
                   → 静态资源带 hash，长缓存
```

`note` 与 `train` 完全走这条，**没有任何 node 进程参与**。

### 6.2 主站接口

```
浏览器 → nginx /say/ 或 /audio/ 或 /portal/
       → https://frp-box.com:64456（樱花，走 TLS + SNI + Host）
       → 笔记本 cipherws-gateway:8080
       → cipherws-say-service:8081（或 portal → Feign → say）
       → 回包原路返回
```

### 6.3 笔记接口

```
浏览器 → nginx /api/auth/login（body: {email, password}）
       → 隧道 → cipherws-gateway:8080
       → 路由 note-gateway-api（Path=/api/**，不剥前缀）
       → note-gateway:8083（校验 JWT → 注入 X-User-Id → 剥掉 /api 再分流）
       → note-user-service:8084 → MyBatis → MySQL(CipherWS)
```

**认证设计（2026-10-20 起）**

- **登录用邮箱**，`email` 是唯一登录标识（`uk_user_email`）。不再用用户名登录，
  所以不会出现「用户名被占用导致注册失败」。
- `username` 降级为**显示名**，注册时由邮箱前缀自动生成（如
  `zhangsan@qq.com` → `zhangsan`），没有唯一约束，用户不用填。
- **注册必须先收验证码**（`purpose=register`）：
  1. `POST /api/auth/send-code {email, purpose:"register"}` —— 后端校验该邮箱**尚未注册**，
     发 6 位码（没配 SMTP 时会写日志并在响应里返回，便于本地联调）
  2. `POST /api/auth/register {email, code, password, nickname}` —— 验码通过才建账号
- 三种验证码用途互不通用：`register`（注册）/ `reset`（找回密码）/ `bind`（换绑邮箱）。
  拿找回密码的码去注册会被「用途不匹配」拦下。
- 登录失败统一提示「邮箱或密码不正确」，不区分邮箱不存在与密码错误，避免枚举账号。

### 6.4 头像

```
上传：POST /api/user/avatar（multipart）
      → 同上链路 → note-user-service 校验（大小/魔数/可解码）→ 落盘 uploads/avatar/ → 写库

访问：<img src="/uploads/avatar/xxx.png">
      → nginx /uploads/ → 隧道 → cipherws-gateway → note-gateway:8083
      → note-user-service 直接吐文件（该路径在网关白名单里，不校验 token）
```

> 为什么头像不鉴权：`<img>` 发不了 `Authorization` 头。
> 安全性靠文件名不可枚举（`用户id-16位随机串.ext`）。

## 七、数据模型（MySQL `CipherWS`，9 张表）

| 表 | 说明 | 关键点 |
| --- | --- | --- |
| `note_user` | 用户 | **`email` 是登录标识且全库唯一**；`username` 只是由邮箱前缀自动生成的显示名（无唯一约束）；BCrypt 摘要 |
| `note` | 笔记 | `deleted=1` 进回收站；`flagged=1` 被管理员标记，**管理员不能改正文** |
| `note_tag` | 标签 | 唯一键 `(user_id, name)`，标签是用户私有的 |
| `note_tag_rel` | 笔记-标签关联 | 外键级联，删标签只解除关联 |
| `note_ai_summary_record` | AI 摘要记录 | 一篇笔记可多次总结 |
| `note_system_announcement` | 系统公告 | `enabled=0` 用户看不到 |
| `note_user_operation_log` | 用户操作日志 | 只增不删 |
| `note_admin_operation_log` | 管理员操作日志 | 只增不删 |
| `note_ai_config` | AI 参数 | 约定 `id=1` 生效；`api_key` 永不回传明文 |

建表脚本：`server/sql/note-schema.sql`（含 9 张表、索引、种子数据：`admin/admin123`、`demo/demo123`）。

| 6 | 证书 | 两张 `.pem` + `.key` 放进 `/etc/nginx/ssl/`，目录 700、证书 644、私钥 600 root:root | 见 3.4 的校验命令 |
| 7 | nginx 配置 | `sudo cp deploy/nginx/cipherws.conf /etc/nginx/conf.d/cipherws.conf`，并挪走自带的 `sites-enabled/default` | `sudo nginx -t` |
| 8 | 前端产物 | `./deploy/update-frontend.sh`（三个站点一起） | 三个域名都能打开 |
| 9 | systemd 单元 | 主站：`cipherws-web.service`（`node server.js --app main`，工作目录 `/opt/cipherws/frontend`） | `systemctl status cipherws-web` |
| 10 | 安全组 | 放行 80 / 443（**端口开放 ≠ 有进程监听**） | `ss -lntp \| grep -E ':80\|:443'` |
| 11 | 备案 | 域名已完成 ICP 备案（子域名共用主域备案） | — |
| 12 | DNS | `@`、`www`、`train`、`note` 四条 A 记录指向 `47.104.253.198` | `dig +short note.cipherws.icu` |

**实测环境限制（会踩的坑）**

- nginx **1.24.0**：只能用 `listen 443 ssl http2;`，写独立的 `http2 on;` 会直接报错。
- 主站 80/443 与 note 80/443 都做了 301 跳转，所以 `curl -I http://cipherws.icu/` 返回 301 是**正常**的。
- 证书只有 90 天，且**没有自动续期**；`/var/www/certbot` 已预留给 certbot。

### 8.3 两台机器之间的依赖

```
笔记本 frpc 是否在线              ← 同上
笔记本 8 个端口是否都在监听       ← 决定网关能否转发
```

### 9.2 ECS：更新前端

```bash
cd /opt/cipherws

# 一条命令：自检 → git pull → 补 .env.production → 装依赖 → 构建 → 重启主站 → 同步 nginx → 自检
```

脚本做的事（按顺序）：

1. 环境自检（git / node / npm / 仓库目录 / 工作区是否干净）
2. `git pull`
3. 检查 `.env.production` 的 `VITE_API_BASE_URL`（必须是空 = 同源），占位地址会被自动纠正
4. 依赖有变动时 `npm install`（或 `--ci` 用 `npm ci`）
5. 构建所选站点 → `frontend/<站点>/dist`
6. 重启主站 systemd 服务（只有 `main` 需要）
7. 同步 nginx 配置：**先备份 → 覆盖 → `nginx -t` → 失败自动回滚 → 通过才 reload**
8. 自检：产物存在性、占位地址残留、本机端口探活

### 9.3 首次上线顺序（重要）

```
1. 笔记本：装 JDK/Nacos/MySQL → 建库导表 → 配 note.env.local → 启动后端
2. 笔记本：frpc 连上隧道，确认公网地址能访问 /say/saying?id=1
3. ECS：装 nginx/node/git → clone 代码 → 放两张证书
4. ECS：cp nginx 配置 → nginx -t → reload（证书没放好之前 nginx -t 会失败）
5. ECS：./deploy/update-frontend.sh 构建三个站点
6. 验证：三个域名逐个打开 + 接口 curl
```

**顺序不能反**：nginx 配置里引用了证书文件，证书不存在时 `nginx -t` 直接失败、`reload` 会被拒绝。

## 十二、故障排查

| 现象 | 最可能的原因 | 怎么确认 / 怎么修 |
| --- | --- | --- |
| 域名打不开、**502** | 静态目录不对，或（主站）8000 没进程 | `ls /opt/cipherws/frontend/<站点>/dist/index.html`；`ss -lntp \| grep 8000` |
| 页面能开、接口 **502** | 笔记本后端没起 / 隧道掉线 / 网关没重新打包 | 笔记本跑 `-Action status`；`curl 127.0.0.1:8080/say/saying?id=1`；隧道地址是否正确 |
| 接口 **404** | 网关缺路由（笔记接口要靠 `cipherws-gateway` 里那两条 `note-gateway-*`） | 重新打包并重启 `cipherws-gateway` |
| 登录成功但一调接口就 **401** | `NOTE_JWT_SECRET` 两边不一致 | 确认网关与 `note-user-service` 读到同一个值 |
| 服务都 UP 但接口 **500** | 数据库密码错 / 库不存在 | `deploy\.logs\note-user-service.err.log` 里找 `Access denied` / `Unknown database` |
| 传头像 **413** | nginx `client_max_body_size` 太小 | 配置里已给 `4m` |
| 头像上传报「只支持 PNG/JPG/WebP」 | 文件头不是真图片 | 魔数校验，不是看扩展名 |
| `nginx -t` 报 `cannot load certificate` | 证书文件缺失/路径不对/权限不对 | 见 3.4 校验命令；**先放证书再 reload** |
| 建表报 `ERROR 1067 Invalid default value` | 客户端字符集不是 utf8mb4 | 脚本已含 `SET NAMES utf8mb4`；也可加 `--default-character-set=utf8mb4` |
| 域名解析到旧 IP | DNS 未生效 / 安全组没放行 | `dig +short note.cipherws.icu` |
| 隧道地址失效（返回别人应用的内容） | 免费隧道公网端口被回收 | 樱花控制台看新地址 → `update-backend-address.sh` 改 |

## 十三、安全要点

| 风险 | 现状与处理 |
| --- | --- |
| 密码泄露 | BCrypt（strength 10）不可逆；对外 VO 里没有 `password` 字段 |
| 越权访问别人笔记 | 每条 SQL 都带 `user_id`，不属于自己的一律「笔记不存在」 |
| 伪造身份头 | 网关**先删**客户端的 `X-User-Id`/`X-User-Role` 再写可信值 |
| 只靠前端拦管理员 | 后端 `Auth.requireAdmin` 二次校验 |
| SQL 注入 | 全部 `?` 占位符；日志切表用常量表名，不用 `${}` |
| AI 密钥泄露 | 只回传掩码；密钥仅存 `note_ai_config`，不进前端产物 |
| 验证码被爆破 | 6 位、5 分钟、用后即失效、同码试错 5 次上限、60 秒频控 |
| 注册被恶意刷 / 冒用邮箱 | 注册必须先验证码（`purpose=register`），证明邮箱归属；且该邮箱**未注册**才发码 |
| 验证码跨用途复用 | `register` / `reset` / `bind` 三种码互不通用，`consumeCode` 校验用途 |
| 生产暴露验证码 | `NOTE_EXPOSE_CODE` 默认 `true` 仅为演示，**上线必须 false** |
| 密钥进仓库 | `.env*`、`*.local`、`*.pem`、`*.key` 全部 gitignore；仓库里只有 `.example` 模板 |
| nginx 版本号外泄 | `server_tokens off;`（可选加固，尚未开启） |
| HSTS | 暂未下发，避免调试期无法回退 HTTP |
