# 笔记系统接口文档

> 对应前端：`frontend/note`（`src/api/index.js` 是唯一接口入口）
> 对应后端：`server/note-*` 六个模块
> 最近更新：2026-10-13

## 一、服务与端口

端口继续遵循「避开 8080/8081/8082（cipherws 网关与业务服务）和 8848/8849（Nacos）」的约定。

| 模块 | 端口 | 职责 |
| --- | --- | --- |
| `note-gateway` | **8083** | 唯一对外入口；按 `/api/**` 分流 + 校验 JWT |
| `note-user-service` | 8084 | 注册 / 登录 / 找回密码 / 个人资料 / AI 额度 |
| `note-core-service` | 8085 | 笔记增删改查 / 回收站 / 标签 |
| `note-ai-service` | 8086 | AI 总结 / 额度扣减 |
| `note-admin-service` | 8087 | 用户管理 / 笔记巡检 / AI 参数 / 公告 / 日志 / 统计 |
| `note-common` | — | 统一响应、业务异常、JWT、鉴权工具（无端口） |

**前端只跟 8083 打交道。** 四个业务服务的端口不应该对公网开放 —— 它们之间的信任建立在「请求只可能来自网关」这个前提上。

## 二、网关路由

网关剥掉 `/api` 前缀后转发：

| 前端请求 | 转发到 | 服务内路径 |
| --- | --- | --- |
| `/api/auth/**`、`/api/user/**` | note-user-service | `/auth/**`、`/user/**` |
| `/api/notes/**`、`/api/tags/**` | note-core-service | `/notes/**`、`/tags/**` |
| `/api/ai/**` | note-ai-service | `/ai/**` |
| `/api/admin/**`、`/api/announcements` | note-admin-service | `/admin/**`、`/announcements` |

## 三、统一约定

### 响应格式

```json
{ "success": true,  "data": {...}, "total": null }
{ "success": true,  "data": [...], "total": 42 }
{ "success": false, "errMessage": "AI 额度已用完，请联系管理员分配" }
```

`total` 只在分页接口出现，是**总条数**（不是当前页条数）。

> ⚠️ 字段名是 **`errMessage`**，不是 `errorMsg`。前端 `request.js` 读的就是这个名字，
> 写成别的会让用户只看到一句笼统的「请求失败」。
> （`cipherws-common` 里那份 `Result` 用的是 `errorMsg`，两套不通用，别混。）

### 鉴权

- 登录成功后 `POST /auth/login` 返回 `token`，前端放在 `Authorization: Bearer <token>`。
- 网关校验通过后，把身份写进请求头转给下游：`X-User-Id`、`X-User-Role`、`X-Username`。
- **网关会先删掉客户端自带的这三个头**，再写入可信值 —— 否则可以伪造身份。
- 免登录白名单：`/api/auth/register`、`/api/auth/login`、`/api/auth/send-code`、
  `/api/auth/reset-password`、`/actuator/**`。
- **`/api/announcements` 不在白名单里**：需求 4.6.4 是「用户登录后可查看公告」，
  而白名单分支是直接放行、不注入身份头的，放进去会让公告接口永远返回「未登录」。
- **网关只校验「有没有登录」，不校验「是不是管理员」**。角色校验在各自服务里做
  （`Auth.requireAdmin`）—— 这样即使网关路由配漏了，接口也不会被越权调用。
- 令牌无效或过期 → 网关返回 **401** + `{success:false, errMessage:"登录已过期，请重新登录"}`。

### 分页

`page` 从 1 开始，`size` 默认 10。SQL 层用 `LIMIT ? OFFSET ?`，`total` 单独 `COUNT(*)`。

### 错误语义

业务异常统一由 `GlobalExceptionHandler` 转成 `success:false`，HTTP 状态码仍是 **200** ——
因为前端的 `request.js` 是先看 `success` 再看状态码，用 200 能让错误提示走同一条通道。
只有网关鉴权失败用 401。

## 四、接口清单

### 4.1 认证（note-user-service）

| 方法 | 路径 | 入参 | 返回 |
| --- | --- | --- | --- |
| POST | `/api/auth/register` | `{username, password, email}` | `UserVo` |
| POST | `/api/auth/login` | `{username, password}` | `{token, user: UserVo}` |
| POST | `/api/auth/logout` | — | `true` |
| POST | `/api/auth/send-code` | `{email}` | `{hint, code?}` |
| POST | `/api/auth/reset-password` | `{email, code, password}` | `true` |

规则：
- `username` **2-20 个字符**，允许中文、英文字母、数字、下划线，全库唯一
  - 前端 `Register.vue`、mock 与后端用的是同一条规则，三处必须一起改 ——
    否则前端先拦下来，后端根本没机会校验
  - 长度按**字符数**算，与 `VARCHAR(20)` 口径一致：一个汉字算 1 个字符
- `password` 至少 6 位，**BCrypt(strength=10) 存储，绝不明文**
- 邮箱格式校验；`send-code` 要求邮箱已注册，验证码 6 位数字、5 分钟有效、用完即失效
- 登录失败统一提示「账号或密码不正确」（不区分账号不存在 / 密码错误，防止枚举账号）
- 账号被禁用 → 「该账号已被禁用，请联系管理员」
- 登录成功写一条 `note_user_operation_log`

> `send-code` 的返回里带不带 `code` 由 `note.auth.expose-code` 控制，**默认 `true`**。
> 这是为了让没有邮件服务时也能跑通找回密码；生产环境必须设 `NOTE_EXPOSE_CODE=false`，
> 否则任何知道邮箱的人都能重置别人的密码。

**UserVo**

```json
{
  "id": 2, "username": "demo", "nickname": "池禾",
  "email": "demo@cipherws.icu", "role": "user",
  "avatar": "", "bio": "...", "aiQuota": 8,
  "enabled": true, "createdAt": "2026-10-01T14:20:00"
}
```

> **时间格式统一为 ISO 8601**（`2026-10-01T14:20:00`），四个服务一致。
> 不能用 MySQL 那种空格分隔的 `2026-10-01 14:20:00` —— 它在 Safari / iOS 上
> `new Date()` 会返回 Invalid Date，前端「3 天前」这类相对时间就会全变空白。

> `UserVo` 里**没有** `password` 字段，这是硬约定。

### 4.2 用户中心（note-user-service）

| 方法 | 路径 | 入参 | 返回 |
| --- | --- | --- | --- |
| GET | `/api/user/profile` | — | `UserVo` |
| PUT | `/api/user/profile` | `{nickname, email, bio, avatar}`（都可空，只更新传了的） | `UserVo` |
| PUT | `/api/user/password` | `{oldPassword, newPassword}` | `true` |
| GET | `/api/user/quota` | — | `{aiQuota}` |

规则：昵称非空且 ≤20 字；简介 ≤120 字；改密码必须先验证原密码，且新密码不能与原密码相同。

### 4.3 笔记（note-core-service）

| 方法 | 路径 | 入参 | 返回 |
| --- | --- | --- | --- |
| GET | `/api/notes` | query: `keyword`、`status`(draft/private)、`tagId`、`page`、`size` | `NoteVo[]` + `total` |
| GET | `/api/notes/{id}` | — | `NoteDetailVo` |
| POST | `/api/notes` | `{title, content, status, tagIds}` | `NoteVo` |
| PUT | `/api/notes/{id}` | `{title, content, status, tagIds}`（都可空） | `NoteVo` |
| DELETE | `/api/notes/{id}` | query: `hard`(true=永久删除，否则进回收站) | `true` |
| GET | `/api/notes/trash` | `page`、`size` | `NoteVo[]` + `total` |
| POST | `/api/notes/{id}/restore` | — | `true` |
| DELETE | `/api/notes/trash` | — | `true`（清空回收站） |

规则：
- **所有查询都带 `user_id` 条件**，访问别人的笔记一律「笔记不存在」（需求 6.2.2 越权拦截）
- `title` 空值兜底成「无标题笔记」；`status` 只认 `draft` / `private`
- 列表按 `updated_at` 倒序
- 删除默认进回收站（`deleted=1`），`hard=true` 才真删

**NoteVo**：`id, title, content, status, flagged, createdAt, updatedAt, tags:[{id,name}]`
**NoteDetailVo** = NoteVo + `summaries:[{id, summary, createdAt}]`

### 4.4 标签（note-core-service）

| 方法 | 路径 | 入参 | 返回 |
| --- | --- | --- | --- |
| GET | `/api/tags` | — | `TagVo[]` + `total` |
| POST | `/api/tags` | `{name}` | `TagVo` |
| PUT | `/api/tags/{id}` | `{name}` | `TagVo` |
| DELETE | `/api/tags/{id}` | — | `true` |

规则：
- 标签名去空格后非空、≤12 字
- **同一用户内不允许重名**（唯一键 `(user_id, name)`），跨用户同名互不影响（需求 7.4）
- **删标签不删笔记**，只解除关联（需求 4.5.3）

**TagVo**：`id, name, createdAt, noteCount`（`noteCount` = 该标签下当前用户未删除笔记数）

### 4.5 AI 总结（note-ai-service）

| 方法 | 路径 | 入参 | 返回 |
| --- | --- | --- | --- |
| POST | `/api/ai/summary` | `{noteId}` | `SummaryVo` |
| GET | `/api/ai/summary` | query: `noteId` | `SummaryVo[]` + `total` |

规则：
- 正文为空 → 「正文为空，无法生成摘要」
- 额度不足 → 「AI 额度已用完，请联系管理员分配」
- **扣额度用 `UPDATE ... WHERE id=? AND ai_quota>0` 原子扣减**，并发下不会扣成负数
- 摘要落 `note_ai_summary_record`，同时写一条 `note_user_operation_log`
- 送进模型的原文按 `ai_config.max_chars` 截断（这是「单次总结最大字数」的含义）

**SummaryVo**：`id, noteId, summary, sourceSnippet, quotaCost, quotaLeft, createdAt`

> 后端**不做本地兜底摘要**。没配密钥就直接报「AI 接口尚未配置密钥」，把问题指向
> 该去修的地方。前端 mock 模式里有假摘要，那只是为了让 UI 能离线演示。

### 4.6 后台（note-admin-service）

所有 `/api/admin/**` 接口在服务层第一行调用 `Auth.requireAdmin(role)` ——
前端已经拦了一层，后端必须自己再拦，前端拦截是体验，后端拦截才是安全。

| 方法 | 路径 | 入参 | 返回 |
| --- | --- | --- | --- |
| GET | `/api/admin/users` | `keyword`、`page`、`size` | `UserVo[]`（含 `noteCount`）+ `total` |
| PUT | `/api/admin/users/{id}/status` | `{enabled}` | `UserVo` |
| PUT | `/api/admin/users/{id}/quota` | `{aiQuota}` | `UserVo` |
| GET | `/api/admin/notes` | `keyword`、`page`、`size` | `InspectNoteVo[]` + `total` |
| PUT | `/api/admin/notes/{id}/flag` | `{flagged}` | `InspectNoteVo` |
| GET | `/api/admin/ai-config` | — | `AiConfigVo` |
| PUT | `/api/admin/ai-config` | `{endpoint, apiKey, model, maxChars}` | `true` |
| GET | `/api/admin/announcements` | `page`、`size` | `AnnouncementVo[]` + `total` |
| POST | `/api/admin/announcements` | `{title, content, enabled}` | `AnnouncementVo` |
| PUT | `/api/admin/announcements/{id}` | 同上（可空） | `AnnouncementVo` |
| DELETE | `/api/admin/announcements/{id}` | — | `true` |
| GET | `/api/admin/logs` | `type`(user/admin)、`keyword`、`from`、`to`、`page`、`size` | `LogVo[]` + `total` |
| GET | `/api/admin/stats` | — | 见下 |

规则：
- 管理员不能禁用自己
- `aiQuota` 必须是 0–9999 的整数
- **笔记巡检只能改 `flagged`，不能改用户笔记的正文与标题**（需求 4.6.2 / 7.3）
- `note_ai_config` 的 `api_key` **永不回传明文**，只给 `apiKeyMasked`（前 6 位 + `********`）；
  请求里 `apiKey` 为空表示「不修改」
- **日志不可删除**，所以没有 DELETE 接口（需求 4.7.4）
- 所有写操作都要落一条 `note_admin_operation_log`

**InspectNoteVo**：`id, title, content, status, flagged, authorName, updatedAt, tags:[{id,name}]`
**AiConfigVo**：`endpoint, model, maxChars, apiKeyMasked, updatedAt`
**AnnouncementVo**：`id, title, content, enabled, createdAt`
**LogVo**：`id, type, detail, actorName, ip, createdAt`

`/api/admin/stats` 返回：

```json
{
  "daily":    [{"date": "2026-10-07", "count": 0}],
  "topUsers": [{"userId": 2, "name": "池禾", "count": 3}],
  "totals":   {"users": 4, "notes": 6, "aiCalls": 3, "flaggedNotes": 0}
}
```

`daily` 固定给**近 7 天**（含今天），没有调用的那天也要出现且 `count: 0` —— 否则前端柱状图的横轴会缺格。

## 六、安全要点（答辩可能会问）

| 风险 | 处理 |
| --- | --- |
| 密码泄露 | BCrypt 不可逆摘要，`UserVo` 不含 password |
| 越权访问别人笔记 | 每条 SQL 都带 `user_id`，不属于自己的一律报「笔记不存在」 |
| 伪造身份头 | 网关先删除客户端的 `X-User-*` 再写可信值 |
| 只靠前端拦管理员 | 后端 `Auth.requireAdmin` 二次校验 |
| SQL 注入 | 全部 `?` 占位符，无字符串拼接 |
| AI 密钥泄露 | 只回传掩码；密钥仅存在于 `note_ai_config` 表，不进前端产物 |
| 并发扣额度扣成负数 | `UPDATE ... WHERE ai_quota > 0` 原子扣减 |
| 验证码被爆破 | 6 位随机、5 分钟过期、用后即失效（多实例需换 Redis） |
| 日志被篡改 | 不提供 DELETE 接口 |

## 七、数据访问层（MyBatis）

数据库访问统一走 **MyBatis**（`mybatis-spring-boot-starter` 3.0.4），不用 JdbcTemplate 拼字符串。

### 分层

```
note-common/entity/      ← 纯 POJO（NoteUser、Note、NoteTag …），八个实体，各服务共用
note-xxx-service/
  ├── mapper/XxxMapper.java   ← 接口，只声明方法签名
  ├── resources/mapper/XxxMapper.xml ← 真正的 SQL
  └── service/impl/…          ← 只留业务逻辑：校验、事务、异常文案、VO 转换
```

实体放在 `note-common` 是为了四个服务共用同一份表结构定义，避免各写一份
`NoteUser` 然后字段悄悄漂移。实体是纯 POJO，不含 MyBatis 注解，所以
`note-common` 不依赖 MyBatis —— 网关也引用它，但网关没有数据库。

### 配置（每个数据服务相同）

```yaml
mybatis:
  mapper-locations: classpath:mapper/*.xml
  type-aliases-package: org.example.cipherws.note.common.entity
  configuration:
    map-underscore-to-camel-case: true    # ai_quota → aiQuota

logging:
  level:
    org.example.cipherws.note.<服务>.mapper: DEBUG   # 能看到实际执行的 SQL 与参数
```

启动类上加 `@MapperScan("org.example.cipherws.note.<服务>.mapper")`。

### 各服务的 Mapper

| 服务 | Mapper | 方法数 | 管什么 |
| --- | --- | --- | --- |
| note-user-service | `UserMapper` | 10 | 账号查询、注册插入、改资料、改密码、写用户日志 |
| note-core-service | `NoteMapper` / `TagMapper` | 15 / 7 | 笔记 CRUD、回收站、标签关联、标签计数 |
| note-ai-service | `AiMapper` | 7 | 取配置、原子扣额度、写总结记录、查历史 |
| note-admin-service | `AdminMapper` / `AdminLogMapper` | 22 / 8 | 用户管理、巡检、AI 配置、公告、两张日志表、统计 |

### 三条必须遵守的约定

1. **XML 的 `namespace` 必须等于 Mapper 接口全限定名，`<select id>` 必须等于方法名。**
   写错了编译期查不出来，运行时才报 `Invalid bound statement (not found)`。
2. **表名一律加反引号**（`` `note_user` ``、`` `note_tag` ``）。`note_user` 的
   `user` 与 MySQL 系统库同名，不加反引号容易在别的库上下文里出错。
3. **动态条件用 `<if>` / `<where>` / `<foreach>`，绝不用 `${}` 拼表名或排序字段。**
   日志按 `type` 切两张表时，用的是两个独立方法 + 两条完整语句，
   表名是编译期常量，不存在注入面。

### 一个容易踩的坑：投影查询用 Map 时没有驼峰映射

只为「连表 + 聚合」的查询（`note_count`、`author_name`、`actor_name`、
统计的 `day`/`calls`）使用 `resultType="map"`。这时：

- **`map-underscore-to-camel-case` 对 Map 不生效**，key 是原始列名，
  必须写成 `row.get("note_count")` 而不是 `note_count→noteCount`；
- **MyBatis 默认不把 NULL 列放进 Map**（`callSettersOnNulls=false`），
  所以「key 不存在」等价于「该列为 NULL」，取值要统一兜底，
  否则 `map.get(...)` 拿到的 null 会一路变成 NPE。

能映射到实体的查询一律映射到实体，只有上面这些投影才用 Map ——
字符串 key 的错拼编译期发现不了，能少用就少用。
