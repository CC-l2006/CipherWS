### 端口分配约定：8000 + 序号

| 子项目 | dev 端口 | 生产如何对外 |
| --- | --- | --- |
| 主站 `main` | **8000** | nginx 反代 `127.0.0.1:8000` |
| 云间列车 `train` | **8001** | nginx 直托 `train/dist`，**不经过端口** |
| 下一个子项目 | 8002 | 依此类推 |

**这些端口只用于本机预览与 nginx 上游，不是站点的公开身份** ——
用户访问的是 `cipherws.icu` / `train.cipherws.icu`，不是 `:8000` / `:8001`。
新增子项目不需要申请新的公网端口。

必须避开的端口：`8080` 网关、`8081`/`8082` 后端服务、`8848`/`8849` Nacos。

### 网关路由（`cipherws-gateway/application.yml`）

```yaml
spring.cloud.gateway.server.webflux:
  discovery.locator.enabled: false      # 关闭按服务名自动映射，只用显式路由
  routes:
    - id: cipherws-say-service     uri: lb://cipherws-say-service      Path=/say/**
    - id: cipherws-audio-service   uri: lb://cipherws-say-service      Path=/audio/**
    - id: cipherws-portal-service  uri: lb://cipherws-portal-service   Path=/portal/**
spring.config.import: optional:nacos:cipherws-gateway.yaml
```

> ⚠️ `spring.config.import` 导入的 Nacos 配置**优先级高于本文件**。若 Nacos 上那份
> `cipherws-gateway.yaml` 里另写了 `spring.cloud.gateway.routes`，会**整体覆盖**上面
> 这份本地路由 —— 这是第九节问题 1 的一个候选原因。

## 九、本次检查发现的问题

### ❌ 1. 后端隧道地址已失效，`frp-hen.com:36691` 现在指向别人的应用

**这是当前唯一影响线上功能的问题。** 实测证据链：

| 探测 | 结果 |
| --- | --- |
| `https://cipherws.icu/` | 200 ✅ 静态站点正常 |
| `https://cipherws.icu/say/saying?id=1` | **404**（Spring Boot 错误 JSON） |
| `https://frp-hen.com:36691/say/saying?id=1`（**绕过 nginx 直连隧道**） | **404** —— 说明 nginx 无辜，是后端侧的问题 |
| `.../portal/say/1`、`.../audio/stream` | 全部 404 |
| `.../`、`/api`、`/say`、`/favicon.ico` 等 11 个路径 | **全部 404** |
| `.../actuator/health` | 200 `{"status":"UP"}` |
| `.../actuator`（索引） | 只列出 `health` 一个端点 |
| 响应头 | `Content-Type: application/vnd.spring-boot.actuator.v3+json` |

**结论：隧道后面确实是个 Spring Boot 3 应用，但不是本项目的任何一个服务。**
依据：项目里三个服务都配了 `management.endpoints.web.exposure.include: health,info`
且 `show-details: always`，而对面只暴露 `health`、且不返回 `components`。

**最可能的原因**：SakuraFrp 免费节点的端口在隧道离线后被回收，`36691` 现在被**别人**
的隧道占用了。你原来的隧道应该拿到的是另一个端口。

**处理**：

```bash
# 1. 到 SakuraFrp 控制台看你当前隧道的真实地址（形如 https://xxx.frp-hen.com:端口）
# 2. 验证它确实是你的后端
curl -s 'https://<新地址>/say/saying?id=1'      # 期望返回 JSON，不是 404

# 3. 改两处（都在同一个仓库里，改完要重新构建前端）
#    deploy/nginx/cipherws.conf  的 upstream cipherws_backend
#    frontend/main/.env.development 的 VITE_API_BASE_URL（本地开发用）
```

顺带一提：现在 nginx 正在把 `/say/`、`/audio/` 的请求转发给**第三方**的应用。
这些请求都是无凭据的 GET，不构成数据泄露，但确实是「请求打错地方」，
建议尽快改掉。更稳的做法是别依赖共享节点的随机端口。

### ⚠️ 2. `www.cipherws.icu` 没有 A 记录

证书覆盖了它、`server_name` 也写了它，但 DNS 查不到 → `https://www.cipherws.icu` 打不开。
加一条 `www A 47.104.253.198` 即可，不用改 nginx。

### ⚠️ 3. `train.cipherws.icu` 没有证书，仍是 HTTP

不是配置问题 —— 主站证书的 SAN 只有 `cipherws.icu` 和 `www.cipherws.icu`，
子域名必须单独签。配置里已预留好整段 443 块，签完取消注释即可。

### ⚠️ 4. nginx 版本号对外暴露

`Server: nginx/1.24.0 (Ubuntu)` —— 默认 `server_tokens on`。加一行 `server_tokens off;`
（放 http 块或每个 server 块）即可隐藏，属于低成本的安全加固。

### ⚠️ 5. `.gitignore` 与 `fetch-jdk17.ps1` 自相矛盾

`.gitignore` 里 `deploy/.tools/` 整目录忽略，但同一文件的注释写着
「由 `deploy/.tools/fetch-jdk17.ps1` 重建」—— 那个脚本也在被忽略的目录里，
**新克隆的人根本拿不到它**。要么把 `fetch-jdk17.ps1` / `dev-env.ps1` 移到
`deploy/` 根目录，要么在 `.gitignore` 里加例外：

```gitignore
deploy/.tools/
!deploy/.tools/fetch-jdk17.ps1
!deploy/.tools/dev-env.ps1
```

### ⚠️ 6. 证书 90 天后到期且无自动续期

`notAfter = Jan 7 2027`。到期后浏览器直接拦截，站点等于不可用。
建议**现在就设日历提醒**，或切到 Let's Encrypt（`certbot`，90 天一续但全自动，
nginx 配置里已预留 ACME 挑战目录）。

### ℹ️ 7. 后端的宽松 CORS 配置现在可以删了

前端已经全部走同源 `/say/`、`/audio/`（实测线上产物里既没有 `frp-hen.com`
也没有占位地址），所以后端那份 `allowedOriginPatterns("*")` + `allowCredentials(true)`
已经没有必要，删掉可以收紧安全面。

## 十、复现命令速查

```bash
# ---------- 本机环境 ----------
node -v && npm -v && git --version
deploy/.tools/jdk-17/bin/java -version

# ---------- 前端依赖与版本 ----------
cd frontend && npm run build          # 两个站点一起构建
node -e "console.log(require('./main/node_modules/vite/package.json').version)"

# ---------- 线上状态 ----------
curl -I  https://cipherws.icu/                                  # 期望 200
curl -I  http://cipherws.icu/                                   # 期望 301
curl -s  https://cipherws.icu/say/saying?id=1                   # 期望 JSON（当前 404）
curl -I  https://cipherws.icu/audio/stream?audio=<文件名>        # 期望 audio/mpeg
curl -I  http://train.cipherws.icu/                             # 期望 200

# 证书详情
echo | openssl s_client -connect cipherws.icu:443 -servername cipherws.icu 2>/dev/null \
  | openssl x509 -noout -subject -issuer -dates -ext subjectAltName

# 隧道是否还是自己的后端（关键排查命令）
curl -s https://frp-hen.com:36691/say/saying?id=1
curl -s https://frp-hen.com:36691/actuator

# ---------- 服务器侧（需 SSH） ----------
nginx -v
sudo nginx -t
sudo ss -tlnp | grep -E ':(80|443|8000)\b'
sudo systemctl status cipherws-web --no-pager
sudo ls -l /etc/nginx/ssl/
```
