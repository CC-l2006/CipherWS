## 二、目录职责说明

| 路径 | 职责 | 说明 |
| --- | --- | --- |
| `frontend\` | 前端主站根目录 | Vue 3 + Vite 工程，构建产物为纯静态资源 |
| `frontend\public\` | 静态资源 | 不经打包直接拷贝到产物根目录，如 `favicon.ico`、`robots.txt` |
| `frontend\src\` | 源码根目录 | 所有业务代码只放在这里 |
| `frontend\src\api\` | 接口封装 | 按后端模块拆文件，统一处理基础地址、错误提示、`success/errMessage` 解包 |
| `frontend\src\assets\` | 静态资源 | 需要参与打包的图片、字体、全局样式 |
| `frontend\src\components\` | 通用组件 | 跨页面复用的展示型组件，不含业务请求 |
| `frontend\src\layouts\` | 布局 | 与路由配合的页面骨架，决定「哪些页面带头部/底部」 |
| `frontend\src\views\` | 页面 | 一、二级路由对应的页面组件，按子系统分子目录 |
| `frontend\src\router\` | 路由 | `index.js` 为路由核心，统一注册路由与布局绑定 |
| `frontend\src\store\` | 全局状态 | 登录态、用户信息、跨子系统共享数据 |
| `frontend\src\App.vue` | 根组件 | 只放 `<router-view>` 与全局容器 |
| `frontend\src\main.js` | 应用入口 | 创建应用实例，挂载路由、状态、全局样式 |
| `frontend\index.html` | 页面模板 | Vite 构建入口 HTML |
| `frontend\vite.config.js` | 构建配置 | 别名、代理、打包输出 |
| `frontend\.env.development` | 开发环境变量 | 如 `VITE_API_BASE_URL` 指向本地后端 |
| `frontend\.env.production` | 生产环境变量 | 如 `VITE_API_BASE_URL` 指向线上后端 |

## 三、关键约定

### 1. 布局（layouts）

| 文件 | 用途 | 典型使用方 |
| --- | --- | --- |
| `DefaultLayout.vue` | 主站布局：顶部导航 `AppHeader` + 页脚 `AppFooter` | `Home.vue`、各子系统首页 |
| `BlankLayout.vue` | 空白布局：只有 `<router-view>`，无公共头尾 | `Login.vue`、独立全屏子系统页面 |

约定：`App.vue` 本身不写导航结构，公共区域一律由布局组件承担，页面只关心自身内容。

### 2. 规划中的页面与子系统对应关系（尚未创建）

> 本节是规划，当前实际只有 `views\Home.vue` 与 `views\Blank.vue`，详见第六节。

| 子系统 | 目录 | 页面 | 定位 |
| --- | --- | --- | --- |
| 主站 | `views\` | `Home.vue` | 门户首页，聚合入口 |
| — | `views\` | `Login.vue` | 登录页，走 `BlankLayout` |
| 子系统 A | `views\cipher\` | `Index.vue`、`Detail.vue` | 列表 + 详情（建议配子路由） |
| 子系统 B | `views\tools\` | `Index.vue`、`Encrypt.vue` | 工具集，含加解密等独立功能页 |
| 子系统 C | `views\admin\` | `Index.vue`、`Users.vue` | 后台管理，建议加登录态与权限守卫 |

### 3. 路由（router\index.js）

> 本节是规划路由表；当前实际只有 `/` 与 `/blank` 两条，见第六节。

建议的路由骨架（`Index.vue` 用布局包裹，`Detail.vue` 等作为子路由）：

| 路径 | 组件 | 布局 |
| --- | --- | --- |
| `/` | `views/Home.vue` | `DefaultLayout` |
| `/login` | `views/Login.vue` | `BlankLayout` |
| `/cipher` | `views/cipher/Index.vue` | `DefaultLayout` |
| `/cipher/:id` | `views/cipher/Detail.vue` | `DefaultLayout` |
| `/tools` | `views/tools/Index.vue` | `DefaultLayout` |
| `/tools/encrypt` | `views/tools/Encrypt.vue` | `BlankLayout` |
| `/admin` | `views/admin/Index.vue` | `DefaultLayout` |
| `/admin/users` | `views/admin/Users.vue` | `DefaultLayout` |

约定：路由用懒加载（`() => import(...)`）；`Detail`、`Encrypt`、`Users` 这类二级页面统一作为一级页面的子路由，便于共用父级布局与激活态。

### 4. 接口层（api）

- 与后端 `server\CipherWS-server` 的接口模块一一对应，接口契约见 `docs\接口文档.md`。
- 通用返回格式统一为 `{ success, errMessage, data, total }`，建议在 `api` 层集中解包：
  成功取 `data`，失败抛出 `errMessage` 并统一提示，页面不直接处理原始响应。
- 基础地址通过环境变量注入（`.env.development` / `.env.production` 的 `VITE_API_BASE_URL`），
  不要硬编码 `http://192.168.8.100:8080`。

## 五、新建文件时遵循的前缀约定

- 通用组件：`App` 前缀表示全局级（`AppHeader`、`AppFooter`），其余按功能命名（`NavMenu`）。
- 布局：`XxxLayout` 统一后缀。
- 页面：统一 `PascalCase` 的 `.vue`，且目录名与路由一级路径同名（`cipher` ↔ `/cipher`）。
